Hephaestus {{ .Values.release.version }} ({{ .Values.release.commit }}) is installed as "{{ .Release.Name }}" in "{{ .Release.Namespace }}".

The migration Job of this revision applies the database migrations, and every role waits for them.
Follow it with:

  kubectl --namespace {{ .Release.Namespace }} logs --follow job/{{ include "hephaestus.name" (dict "root" . "component" "migration") }}-{{ .Release.Revision }}

Then open https://{{ .Values.host }}.

{{ if .Values.worker.enabled -}}
Each worker runs the sandbox isolation probe before it becomes ready. A worker that stays unready logs
each check that the cluster failed:

  kubectl --namespace {{ .Release.Namespace }} logs deployment/{{ include "hephaestus.name" (dict "root" . "component" "worker") }}
{{ else -}}
No worker is enabled, so practice reviews and conversation turns do not run.
{{ end -}}
{{ if and .Values.postgresql.bundled (not .Values.postgresql.backup.enabled) }}
WARNING: the bundled PostgreSQL has no backup. postgresql.backup.enabled is false, so the chart does
not archive the WAL and takes no backup. If the PostgreSQL volume is lost, all data of every
workspace is lost. Enable the chart's pgBackRest backup, or back up the volume yourself:

  https://docs.hephaestus.build/admin/backup-restore#turn-on-the-chart-backup

{{ end -}}
