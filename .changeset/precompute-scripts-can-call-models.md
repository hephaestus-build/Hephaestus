Practice precompute scripts can ask models to rate or find the places that a review must check. If you assign no such model, practice reviews run as before.

- **Write.** The practice editor has its own **Precompute script** section, after **When this practice is reviewed**. It links to **AI models** and to the new guide [Write a precompute script](https://docs.hephaestus.build/admin/precompute-scripts). The guide has a tutorial, patterns, a local test command, and a brief for an AI assistant. **Technical settings** keeps the identifier and feedback delivery. It no longer opens by itself when the practice has a script.
- **Connect.** The **API** select of the connection form offers three more APIs for precompute scripts. They are the **Decisions API**, the **Embeddings API** and the **Rerank API (Cohere-compatible)**. The API cannot change after you create the connection. When such an endpoint lists no models, you add the model by its ID. Each connection shows an icon for each kind of model that its API serves.
- **Assign.** **AI models** has a second section, **Models for precompute scripts**. It has a **Decision model**, an **Embedding model** and a **Reranking model**. Each row shows one column for each tier, and a badge only when it needs a decision. An open row lists the practices that use the model, with unmet needs first. Links such as **Assign a decision model** open the right row.
- **Data handling.** Precompute calls follow the reviewed developer's AI choice. A precompute model is at least as strict as the review's own model. If a review runs on an In-house model, its scripts use only In-house models. A Cloud precompute model that no Cloud review can use shows a note.
- **See each script.** A review has a section **Precompute scripts**. It shows each script's result, its models with their tier, its calls and its run time. It also shows why calls were not rated, and the first line of a failed script's error.
- **What it saw.** On a piece of work, **What it saw** has one line for each script. The line has at most one link that fixes the cause, and **Details**.
- **See the review's models.** **How this review ran** shows the model with its tier and counts **Review model calls**. **Practice setup** shows an alert when some members do not get a required model. It lists the script's needs beside its code.
- **See the cost.** **AI usage** and each workspace's details on the instance page have a section **Precompute models by practice**. It splits the cost of each decision, embedding and reranking usage row between practices. Cost that no practice can carry shows as **Not attributed**. Chat calls from a script stay in the review's own cost.
- **Usage tables.** Money columns are grouped by purse, **Shared models** and **Own provider**. For each purse, **By run type** shows **Spend** and **Avg per run**. **Precompute models by practice** shows **Spend** and **Avg per review**. **By day** shows the spend of each purse.
- **Averages and unpriced usage.** An average column shows the same decimals in each cell, such as `$0.004` below one cent. **No price set** appears only when a row has unpriced usage. It counts runs, or reviews in the table by practice, not usage rows. **Runs** counts review attempts and Heph turns only.
- **Budget and cap.** The instance table of workspaces shows the spend of each purse, the shared-model budget, and the provider cap. **Own provider** shows when the month has usage on the workspace's own provider. In the current month, it also shows when the workspace has an enabled model on its own enabled connection. Thus, you can set a provider cap before the first call.
- **Tiles and buttons.** The tiles show the budget or cap, such as `of $25`. They also show **Paused**, **Near the budget**, **Near the cap** or **No price set**. The workspace's cap button names the cap that it changes: **Set provider cap** or **Change provider cap**.
- **Sorting.** The table by practice sorts by each column except **Models**. The instance table of workspaces sorts, filters by name, and shows 25 workspaces on each page.
- **Limits.** Precompute calls count against the same shared-model budget and provider cap as review calls. Each review attempt has an attempt token limit of 200,000 tokens for its precompute calls. To change it, set `PRACTICE_REVIEW_PRECOMPUTE_MAX_TOKENS_PER_ATTEMPT`. When the limit, the budget or the cap is spent, the proxy refuses further precompute calls with HTTP 402. The review continues without them.
- **No metered API cost.** A model with **No metered API cost** always records a confirmed $0, also without reported tokens.
- **Time.** A practice-review timeout below 151 seconds now runs at 151 seconds. The precompute scripts take up to a tenth of the timeout, at most 90 seconds. Each script runs in its own process without the review's credentials. A script that never finishes loses only its own practice's results.
- **Monitor.** `agent.review.precompute.scripts` counts each script's outcome by `status`. `llm.proxy.precompute.unattributed` counts precompute calls that the proxy refused because they named no practice. It stays at 0 when the agent image matches the server's release. `llm.proxy.budget.blocked` has a new `cap` tag. It names what refused the call: `instance`, `byo` or `precompute_attempt`.
