## Heph session ownership

Web chat and Slack DMs retain their front ends, admission, budget checks, persistence and
`fetch_context` on the server. `WorkerInteractiveSandboxService` places a session on a connected
worker with spare mentor capacity. The worker hub carries bounded session commands, acknowledgements,
runner frames and terminal session events; the runner itself opens an outbound WebSocket to the
worker's Sandbox Gateway. The worker owns attachment, idle eviction, Docker resources and session
metrics. No server-side Docker fallback exists.

Each live developer/workspace session stays on its worker. The server transfers only a scoped proxy
credential and its non-secret route; the worker resolves provider keys and binds each turn before
sending the prompt. Proxy usage is committed to PostgreSQL, not reconstructed from runner claims.
Drain and control-connection loss retire sessions. The next turn restores `session_jsonl` on an
available worker; absence of spare capacity is a retryable “Heph is busy” result.

A prepare acknowledgement or `runner_ready` does not prove SDK readiness. The server records
`mentor.turn.runtime_ready` only after `open_thread` completes, at the real runtime boundary.

## Why mentor traffic is sticky

A Heph runtime container opens its gateway frames WebSocket to the **owning worker**, not to the application server. The worker owns the sandbox registry and idle eviction; the server relays JSON-RPC frames through the authenticated hub and retains `chat_thread.session_jsonl` in PostgreSQL. A saved session travels with `open_thread`, so the next turn can restore it after worker eviction, drain or restart. Preparation and a following web turn keep the same server affinity and worker placement; Slack preparation and a DM handled by different server replicas may still open separate placements. The reference single-server deployment avoids that case.

Traefik pins workspace traffic to the originating replica via a cookie scoped to `/api/workspaces` — narrower than the full `/api` router (auth and public endpoints stay round-robin), broad enough to cover the actual mentor URL `/api/workspaces/{slug}/mentor/chat`. Labels live on the `https-application-server` service in `docker/compose.app.yaml`. Inspect with `curl -i`:

- Cookie: `__Secure-hep_workspace_aff` — `Secure`, `HttpOnly`, `SameSite=Lax`, `maxAge` follows `hephaestus.mentor.idle-ttl-seconds` (900 s default). Traefik writes the cookie only when it picks a replica, so the affinity lasts that long from the first request rather than from the last one.
- Response header: `X-Hephaestus-Replica: <container-id-prefix>` — emitted by `ReplicaIdentityFilter` from `$HOSTNAME`, CORS-exposed for the webapp.

Labels are HTTPS-only; the HTTP router redirects to HTTPS, so pinning it would just double-issue cookies. The `cookie.path` attribute requires Traefik >= 3.3. Previews (`docker/preview/compose.app.yaml`) are single-replica and omit the labels.

## Known limitations

- **Two browsers, same user.** Two browsers can pin to two replicas, each spawning its own `(userId, workspaceId)` sandbox — `InteractiveSandboxRegistry` is per-JVM.
- **Slack has no affinity.** Slack events reach the server through shared durable NATS consumers, so with more than one application-server replica the `app_home_opened` that prepares a sandbox and the DM that follows can land on different replicas; the DM then starts its own. A single replica, the reference topology, always reuses it.
- **Rolling deploys.** A worker drain ends its Heph sessions with a terminal stream result. The next turn restores the saved thread on an available worker. The `SseEmitter` timeout remains 10 minutes (`MentorChatController.EMITTER_TIMEOUT_MS`); it is not the worker-drain deadline.

## Disabling affinity for debugging

Delete the `traefik.http.services.https-application-server.loadbalancer.sticky.*` labels from `docker/compose.app.yaml` and redeploy. Existing sessions stay pinned until the cookie expires; new sessions round-robin. Expect transient 5xx on reconnects that land on a cold replica.
