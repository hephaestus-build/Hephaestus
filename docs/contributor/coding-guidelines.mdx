These guidelines keep every service aligned. Keep changes focused. Mention any deviation in your pull request. Raise follow-up issues when you discover gaps.

## Contributor checklist

- Run the formatter and linter for the area you touched. Examples: `vp run format:webapp`, `vp run lint:java`.
- Smoke-test the critical scripts. `vp run build:webapp` must pass. If you changed migrations, run `vp run db:generate-erd-docs`.
- Update Chromatic snapshots when you change UI components.
- Regenerate clients and documentation when you change an API contract.
- Run the [local verification](./local-verification.mdx) appropriate to your changes.
- Document what you verified in the pull request template. Link failing checks to tickets if you must defer.

## Webapp (`/webapp`)

### Platform overview

- React 19 on Vite. Read the pinned versions from `webapp/package.json`; they move faster than this page.
- React Compiler is enabled in `webapp/vite.shared.ts`, which every build of app source pulls in. Leave it on.
- Routing uses TanStack Router file routes in `src/routes/**` with the generated `routeTree.gen.ts`.
- TanStack Query v5 is initialised in `src/integrations/tanstack-query/root-provider.tsx`. OpenAPI helpers live in `src/api/@tanstack/react-query.gen.ts`.
- Global state lives in Zustand stores under `src/stores/**`.
- Tailwind CSS 4 powers styling. Tokens sit in `src/styles.css`. shadcn/ui primitives live in `src/components/ui/**`, which is a registry install over Base UI — check a change there against upstream and record a deliberate divergence in the file, because re-vendoring overwrites it.
- Storybook, Chromatic, Vitest, oxlint, and oxfmt cover tooling.

### Building features

- Create routes with `createFileRoute`. Route modules handle auth gating (see `src/routes/_authenticated.tsx`), loader logic, and orchestration.
- Keep presentational components in `src/components/**`. They should take props, stay pure, and avoid side effects.
- Fetch data by spreading generated `...Options()` helpers into `useQuery` or `useMutation`. The helpers provide typing, query keys, and retry defaults. A hand-written query key is a lint error (`hephaestus/no-manual-query-key`), because it stops matching the generated one silently.
- Invalidate caches with the generated `...QueryKey()` helpers or the same keys passed to `useQuery`. Use optimistic updates only when the UI must respond instantly, such as mentor chat streaming.
- Subscribe to Zustand stores with selectors (`useDocumentsStore((state) => state.documents[id])`). Keep store actions pure.
- The React Compiler rules and the clock rules are `webapp/AGENTS.md` § React Compiler and § The time of day; both are enforced by lint.
- Stay inside the `--color-*` token scale declared in `src/styles.css`. Reach for shadcn/ui primitives before adding new component libraries. `@apply` lives in `styles.css` for base and wrapper rules, not in components.
- Co-locate `*.stories.tsx` files. Show the states the component can actually reach, with realistic data. Run `vp run --filter webapp chromatic:ci` whenever stories change.
- Defer analytics work to effects that run after paint.

### Onboarding and choice screens

The sign-in setup page (`ConsentPage`) and the workspace setup page (`WorkspaceOnboardingPage`) are
one product surface, and every screen that asks a developer to decide something follows the same
rules. Each rule names the source it comes from.

- **One question per page; the heading is the question.** A screen carries one decision and zero or
  more actions that are not decisions; actions go in a section below the answer, never on a second
  page. — [GOV.UK question pages](https://design-system.service.gov.uk/patterns/question-pages/)
- **No step counter, no progress bar.** A total is a claim about a flow the screen cannot see; a
  `StepMarker` per section claims only "this part is answered". — GOV.UK question pages, and the
  `ConsentPage` JSDoc.
- **Never pre-select an answer.** `value={choice ?? null}` on a first visit. A saved answer shown
  checked on a return visit is the current fact, not a default, and the copy says so. —
  [GOV.UK radios](https://design-system.service.gov.uk/components/radios/)
- **Answers are equally weighted.** Same card, title plus one sentence, one same-size icon on every
  answer including No AI, no benefit attached to one; EDPB condemns asymmetry, not icons. What
  explains the choice lives in a `FactList` above the group, addressed to every answer. — [EDPB 03/2022 § 4.2](https://www.edpb.europa.eu/system/files/documents/2023-02/edpb_03-2022_guidelines_on_deceptive_design_patterns_in_social_media_platform_interfaces_v2_en_0.pdf)
- **Declining costs the same click as accepting, and changing later is one sidebar click to the
  same cards.** No confirmation dialog on choosing or leaving No AI. — [GDPR Art. 7(3)](https://gdpr-info.eu/art-7-gdpr/),
  [NN/g on confirmation dialogs](https://www.nngroup.com/articles/confirmation-dialog/)
- **Consequences are read once, before choosing, never behind a disclosure.** — EDPB 03/2022 "Left
  in the dark"; [Hick's law](https://lawsofux.com/hicks-law/)
- **An answer the workspace has not set up yet stays selectable, with the consequence in the card
  text.** The answer is a boundary, not a pick from today's models: nothing runs for that purpose,
  the card and Heph say so, and never an automatic switch to another answer. —
  [Inactive buttons](https://www.uxtigers.com/post/inactive-buttons)
- **Optional stages say so in their heading; a stage with nothing in it is not rendered.** —
  [W3C multi-page forms](https://www.w3.org/WAI/tutorials/forms/multi-page/)
- **One primary per state.** `Continue` when it moves the flow on, the specific verb when it does one
  thing (`Connect Slack`, `Save`). Two primaries side by side is a wizard bug. —
  [NN/g wizards](https://www.nngroup.com/articles/wizards/)
- **A disabled submit carries its reason in visible text wired through `aria-describedby`.** A native
  disabled button is out of the tab order, so the reason must be readable elsewhere. —
  `webapp/AGENTS.md` § Role-based gating
- **The exit is always reachable and says what it leaves behind.** A look-only visit needs no server
  write to leave; the flow ends on the page the reader was going to, never on a "Done" interstitial.
  — NN/g wizards; [peak-end rule](https://lawsofux.com/peak-end-rule/)
- **App-authored explanation is cut to a `FactList`; there is no owner-authored welcome text.** —
  [NN/g on cognitive load](https://www.nngroup.com/articles/minimize-cognitive-load/)
- **The visual language is `ConsentPage`'s and nothing else.** `bg-background`, `PageLayout
  max-w-2xl`, Heph speaking from `HephSays`, the `--mentor` accent only where Heph speaks, `LegalLinks`
  at the foot. No decorative background and no entrance motion: ornament masks faults, and the page
  arrives right after one that has neither. — [Aesthetic-usability effect](https://lawsofux.com/aesthetic-usability-effect/);
  motion rules in `webapp/AGENTS.md` § Motion
- **One name per thing on every surface the member sees.** The member's choice is "your AI choice" in
  the sidebar, the notice, the heading and the copy; "Member onboarding" is the owner's page. A
  consequence sentence is written once and quoted, not paraphrased.

### Quality gates

- Install dependencies with `vp install` at the repo root so optional binaries resolve.
- Run `vp run check:webapp` and `vp run build:webapp` before opening a pull request.
- Execute Vitest suites with `vp run test:webapp`. Add unit tests beside the feature you touched.
- Keep Storybook stories in sync with design. Launch `vp run --filter webapp storybook:dev` when pairing with design reviews.
- Validate bundle impact by checking the Vite build stats when you add large libraries.

## Spring Boot application server (`/server`)

### Structure

- Feature packages sit directly under `de.tum.cit.aet.hephaestus` — `practices/`, `evidence/`, `agent/`, `integration/`, `mentor/`, `workspace/`, `leaderboard/` and the rest. Shared wiring sits in `config/` and `core/`. Cross-cutting integration traits (webhook ingress, oauth ingress, SPI, registry) live under `integration/` directly. `ls` the package root rather than trusting a list here.
- Controllers return DTOs located near the controller. `LeaderboardEntryDTO` is the reference example.
- Repositories return `Optional<T>` instead of `null`.
- Services take their collaborators through the constructor, over `private final` fields; field injection with `@Autowired` is not used. If a service depends on many collaborators, split the responsibility.
- Set up loggers with `LoggerFactory.getLogger`. Use structured log messages.
- Annotate the smallest unit of write work with `@Transactional`.

### Coding habits

- Use Java 21 features where they simplify code. Records, pattern matching, and sealed hierarchies improve readability.
- Keep controllers thin. Push orchestration into services and prefer constructor helpers over static util classes.
- Expose dedicated DTO mappers in the package instead of sprinkling conversion logic across layers.
- Treat `Optional` as a signal for missing data. Avoid returning `null` from repository methods.

### Null safety

- `server/AGENTS.md` § Null-safety owns the NullAway policy. On API DTOs, use explicit `@NonNull` for components that must be `required` in OpenAPI.
- Run `vp run gate:java-nullness` for the policy check and `cd server && ./gradlew :application:testClasses` for compiler analysis.

### Safe workflows

- Configuration overrides stay in `application-*.yml`. Do not commit `application-local.yml`.
- Share long-lived infrastructure in tests. Lean on Testcontainers and GitHub fixtures where possible.
- After updating Liquibase migrations, run `vp run db:generate-erd-docs`. Regenerate OpenAPI and
  the REST client only when the HTTP API contract changes.
- Run the affected [test tiers](./testing.mdx#gradle-recipes), including architecture checks when changing module boundaries.
- Prefer integration tests that extend `BaseIntegrationTest`, or `AbstractWorkspaceIntegrationTest` for anything workspace-scoped, when you touch persistence logic. See [Testing](./testing.mdx).

## Webhook receiver (`server/.../integration/core/webhook/`)

- `server/AGENTS.md` § Webhook receiver owns the layout, the role gate, the subject grammar, the
  ArchUnit guards and the JaCoCo floors.
- The provider-specific verifiers and subject parsers are Spring-free and live with their provider,
  under `integration/scm/github/webhook/` and `integration/scm/gitlab/webhook/`. All are exercised by
  JUnit unit tests plus parameterised tests over the captured fixtures in
  `server/application/src/test/resources/{github,gitlab}/`.
- HMAC verification uses `MessageDigest.isEqual` (constant-time, length-tolerant).

## Docs site (`/docs`)

- Docusaurus 3 powers the documentation. Install dependencies with `vp install` and run
  `vp run docs:dev` from the repository root to preview.
- Keep the front matter `id` and `title` unique, and add every new page to `sidebars.*.ts` — the sidebars are explicit.
- Use MDX components from `docs/src/components/**` to keep styling consistent.
- Run `vp run docs:build` before committing structural changes to confirm the static export succeeds.

## Database and migrations

- Liquibase `<changeSet>`s (schema deltas — not release changesets) live in `server/application/src/main/resources/db/changelog/`. A schema change also needs a release changeset — `.changeset/README.md`.
- Prefer `renameColumn` or `modifyDataType` when evolving schemas so data survives deployments.
- Add indexes before backfilling large tables. Profile long migrations locally.
- After schema updates, regenerate the ERD and run server tests that touch the affected tables.

## Observability and security

- Sentry is configured in both the webapp and the application server. Capture exceptions with context tags instead of console logs.
- Store shared secrets in LastPass and load them via `.env` or the respective `application-*.yml` files. Never commit real secrets.
- Rotate API keys when you onboard new external services. Document the process in `docs/runbooks/`.
- Sanitise logged user data. Log IDs rather than emails.

## Performance reminders

- Batch network calls and paginate large results.
- Cache expensive computations when you reuse them. TanStack Query handles client caching. Use memoised services or projections on the server.
- Measure before tuning. Add logging or metrics when you touch critical latency paths.
- Profile React work with the DevTools profiler and Chrome Performance panel. Profile Java code with JFR and async-profiler.

## When unsure

Record trade-offs in your pull request. Ask for a second review on risky work. Suggest improvements to this page when you find a better pattern.
