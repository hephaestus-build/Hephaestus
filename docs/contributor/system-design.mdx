## Top-level architecture

![Hephaestus top level architecture](./img/system-design/top_level_architecture.svg)

The React client talks to a Spring Boot application packaged as one JAR. Its **server**, **worker**,
and **webhook** runtime roles can run together or in separate containers; [runtime roles](/admin/runtime-roles)
owns their configuration and deployment boundaries.

GitHub, GitLab, Slack, and Outline adapters provide project work and context for practice reviews
and mentoring. The [practice-review pipeline](./practice-review-pipeline.mdx) defines how reviewed
work becomes observations and delivered feedback.

## Practice review module boundaries

`agent` owns review execution and orchestration; `practices` owns revisions, observations, feedback,
and the review gate. The [practice review pipeline](./practice-review-pipeline) owns their lifecycle
and refusal semantics.

Observation admission uses `integration.scm.ReviewTargetQuery` for SCM identity rather than SCM
entities or repositories. Identity lookup does not authorize workspace access or feedback delivery.

The integration modules are [open](https://docs.spring.io/spring-modulith/reference/fundamentals.html#modules.open),
so Modulith verification does not enforce their persistence encapsulation.
`PracticeReviewModuleBoundaryTest` guards the SCM admission boundary, not the entire review pipeline.

## AI mentor architecture

Heph uses a Pi sandbox and streams responses to the client over SSE.
[Unified Pi runtime](./unified-pi-runtime.mdx) documents sandbox connections and replica affinity.

## User interaction flows

![AI mentor use cases](./img/system-design/mentor_use_cases.svg)

Developers review work, receive practice feedback, and talk with Heph. Workspace administrators
choose the connected sources and enabled features. Optional leaderboards and leagues remain
separate from practice feedback.

## Core workflows

### Login and authorisation

![GitHub login and authorisation flow](./img/system-design/login_authorization_flow.svg)

[Native authentication](https://github.com/hephaestus-build/Hephaestus/blob/main/docs/decisions/0017-replace-keycloak-with-spring-native-auth.md) describes

### New review activity

![New review activity workflow](./img/system-design/new_review_activity.svg)

The webhook role verifies provider events and publishes them to NATS JetStream for the server’s
integration consumers. [Webhook ingestion operations](/admin/webhook-ingestion-operations)
documents transport, retention, and recovery.
