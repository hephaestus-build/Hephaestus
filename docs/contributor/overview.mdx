The Applied Education Technologies (AET) team at TUM maintains Hephaestus.
Hephaestus gives developers practice feedback on pull requests, merge requests, and issues.
It includes Heph, a conversational AI mentor.
This guide covers the codebase and development workflow, from local setup to production releases.

## Repository layout

```text
Hephaestus/
├── webapp/                    # React + Vite front-end (public UI)
├── server/                    # Gradle multi-project build
│   ├── application/           # Spring Boot application — server, worker, and webhook roles
│   └── generated-clients/     # Generated GitHub, GitLab, and Outline transports
├── docs/                      # Docusaurus site (this documentation)
└── scripts/                   # Tooling (ERD generation, migrations, utilities)
```

The webhook receiver lives under `integration/core/webhook/` in the application module and runs
in its own container in production — [Runtime roles](../admin/runtime-roles#monolith-vs-split-pod).

## Where the architecture decisions live

The ADRs are intentionally **not on this site**.
They live in the repository under
[`docs/decisions/`](https://github.com/hephaestus-build/Hephaestus/tree/main/docs/decisions).
[`decisions/README.md`](https://github.com/hephaestus-build/Hephaestus/blob/main/docs/decisions/README.md) indexes them.
They refer to internal class names, so their reader already has the repository open.
The PR that changes the code also amends the applicable ADR.
The same applies to `docs/runbooks/`, `docs/auth-architecture.md` and `docs/auth-glossary.md`.

Two rules when you touch them:

- **Link them by absolute GitHub URL** from any page on this site. A relative `../decisions/…` link
  resolves to nothing here and fails the docs build (`onBrokenMarkdownLinks: 'throw'`).
- **An ADR records a decision, not a fix log.** Record a later bug fix in a changeset.
  Amend an ADR only when the decision or one of its consequences changed.
