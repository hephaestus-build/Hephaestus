A public activity page shows the human contributions to a workspace's public repositories, to anyone and without sign-in.
Public activity pages are off by default.
While they are off, no workspace can publish a page, and every public page stops.
Use this procedure to allow them on your instance.
Workspace admins then publish their own page, as [Publish a public activity page](/user/publish-public-activity) describes.

## Before you start

- You need the instance admin role and a recent sign-in.
- Determine the lawful basis for the publication, and add the notice text to your privacy notice.
  [The public activity page](./legal-pages#the-public-activity-page) gives the text.
- Check the activity history of the workspaces, as the [activity history runbook](./activity-history-repair.mdx) describes.

## Allow the pages

1. Open **Instance administration → Instance settings**.
2. Under **Public activity pages**, turn on **Allow public activity pages**.

The switch shows the saved choice.
A saved choice takes precedence over the chart default, and the audit log records each change.

## Set the chart values

Two chart values control public activity pages:

```yaml title="values.yaml"
config:
  publicActivity:
    # The default of Allow public activity pages, until an instance admin saves a choice.
    enabled: false
    # How long a repository stays on public pages after its last confirmed metadata sync.
    repositoryVisibilityMaxAge: 48h
```

A page shows a repository only while a recent sync confirms that the repository is public.
If metadata syncs stop or fail, the repository leaves the page no later than `repositoryVisibilityMaxAge` after the last successful sync.
Set it to twice your metadata sync interval. The value must be a positive duration.

Run the install command again after you change a value.

A repository that becomes private leaves the page at the next metadata sync.
On GitLab, a system hook with the `project_update` event reports the change at once.
Project and group webhooks do not report visibility changes.

## Check that it worked

1. Ask a workspace admin to publish the page of their workspace.
2. Open the address that **Workspace settings** shows, in a private browser window.
3. Check that the page lists only public repositories and the people who chose to show.

## Undo

1. Open **Instance administration → Instance settings**.
2. Turn off **Allow public activity pages**.

Every public page stops on the next request.
A response that a browser already received stays on that screen until the page loads again.

## What a public page serves

- Every response carries `Cache-Control: no-store`.
- An unknown, inactive, or unpublished page returns the same not-found answer.
- Unless a workspace [allows search engines](/user/publish-public-activity#let-search-engines-list-the-page), the API sends `X-Robots-Tag: noindex`, and the web app sets a `noindex` robots meta tag with JavaScript.
- Anonymous requests share a limit of 60 per minute for each client IP address, across all workspaces. Signed-in requests do not count. The chart has no value to change this limit.
- The rate limiter refuses requests when its backend is unavailable.
