---
title: Protect admin access with passkeys
description: Set the passkey policy of your instance with the Helm chart, and recover an admin who lost every passkey and recovery code.
page_type: how-to
---

A passkey protects admin access after the sign-in provider identifies the account.
By default, the Helm chart requires a passkey for instance administration.
Each admin registers their own passkeys and recovery codes, as the user guide's [Passkeys](/user/passkeys) describes.

## Set the passkey policy {/*#configure-the-policy*/}

1. Add the policy to `site.yaml`.
   The block shows the defaults of the chart:

   ```yaml title="values.yaml"
   config:
     auth:
       passkeys:
         instanceAdminRequired: true
         workspaceAdminRequired: false
         rpId: ""
         allowedOrigins: []
         adminMaxAge: 6h
   ```

2. Apply `site.yaml`.
   On a cluster, run the `helm upgrade` command of [Install](./kubernetes#install) again.
   On one host, run the installer again ([Run the installer](./k3s#2-run-the-installer)).

| Value | Effect |
| --- | --- |
| `config.auth.passkeys.instanceAdminRequired` | Require a passkey for instance administration and for elevation to a workspace. |
| `config.auth.passkeys.workspaceAdminRequired` | Require a passkey for the administration of every workspace. Without it, each workspace chooses with **Require admin passkeys**. |
| `config.auth.passkeys.rpId` | The domain that owns the passkeys. Empty uses `host`. |
| `config.auth.passkeys.allowedOrigins` | The HTTPS origins of the web app where browsers use passkeys. Empty uses `https://<host>`. |
| `config.auth.passkeys.adminMaxAge` | How long one passkey verification opens protected admin access |

Set the origin that the browser shows, not an internal address of the API.
Never add an origin that another party controls.
A change of `rpId`, or of `host` while `rpId` is empty, makes every registered passkey unusable.
After such a change, each admin recovers with a recovery code and registers a new passkey.
An admin without a recovery code needs [deployment-controlled recovery](./passkeys.mdx#deployment-controlled-recovery).

A passkey policy applies only when an account uses an admin capability.
Member access never needs a passkey.
The browser extension and other installed clients cannot verify a passkey, so protected administration needs the web app.

After `adminMaxAge`, the admin verifies a passkey again, and the session continues.
High-risk admin operations need a verification within the last five minutes.
The chart has no value that changes these five minutes.

## Test instances without additional confirmation

`config.auth.assuranceEnforced` is `true` by default.
Set it to `false` only on an isolated test instance that runs unattended checks.
It suspends every passkey and recent-sign-in requirement, also the personal and workspace policies.
Sign-in, sessions, roles, workspace permissions, consent and the audit log still apply.
Views as another user stay read-only.

The settings then show that confirmation checks are off.
Saved policies, passkeys and recovery codes stay unchanged, and apply again when you set the value back to `true`.
Do not use this value to recover a production account.

## Check that it worked

1. Sign in as an instance admin who has a passkey.
2. Open **Instance administration**.
   With `instanceAdminRequired`, Hephaestus asks you to select **Confirm with passkey**.
3. Confirm with your passkey.
   The page opens.

## Recover an admin who lost every passkey {/*#deployment-controlled-recovery*/}

Use this procedure only when an admin lost every passkey and every recovery code.
The first-admin bootstrap token cannot recover an existing admin.

1. Confirm the identity of the account owner outside Hephaestus.
2. Record the approval in your incident record.
3. Connect `psql` to the application database with an operator account.
4. Set `account_id` to the numeric ID of the account, and run the script.
   Stop if the `SELECT` shows another person or an account that is not active.

   ```sql
   \set ON_ERROR_STOP on
   \set account_id 42
   SELECT id, display_name, status FROM account WHERE id = :'account_id'::bigint;

   BEGIN;
   SELECT id FROM account WHERE id = :'account_id'::bigint FOR UPDATE;
   UPDATE account SET passkey_recovery_required = true
   WHERE id = :'account_id'::bigint AND status = 'ACTIVE';
   DELETE FROM passkey_challenge WHERE account_id = :'account_id'::bigint;
   DELETE FROM passkey_recovery_code WHERE account_id = :'account_id'::bigint;
   DELETE FROM passkey_credential WHERE account_id = :'account_id'::bigint;
   UPDATE client_sign_in_handoff SET consumed_at = now()
   WHERE account_id = :'account_id'::bigint AND consumed_at IS NULL;
   UPDATE client_session SET revoked_at = now(), revoked_reason = 'ADMIN_REVOKE'
   WHERE account_id = :'account_id'::bigint AND revoked_at IS NULL;
   UPDATE issued_jwt SET revoked_at = now(), revoked_reason = 'ADMIN_REVOKE'
   WHERE account_id = :'account_id'::bigint AND revoked_at IS NULL;
   INSERT INTO auth_event (account_id, event_type, result, details)
   VALUES (:'account_id'::bigint, 'PASSKEY_CHANGED', 'SUCCESS',
           '{"passkey_operation":"deployment_recovery"}');
   COMMIT;
   ```

5. Tell the owner through a verified channel.
6. The owner signs in, registers a new passkey, and verifies it.

The script removes the passkeys and recovery codes of the account, and ends its sessions.
Admin access stays blocked until the owner verifies the new passkey.
Do not turn off `instanceAdminRequired` to recover an account.
