# Practice catalog

The instance catalog supplies practices and practice groups for workspaces to adopt.
Workspace copies have independent versions and operational settings.
Changing the instance entry does not silently rewrite a workspace practice.

## Include and exclude entries

Instance admins control whether workspaces can adopt each entry.
Exclude makes it unavailable for new adoption. Include reverses that choice.
Existing workspace definitions and earlier observations remain unchanged.

## Adopt and customize

A workspace admin adopts a practice from the catalog.
Its complete definition becomes a fixed workspace version.
The workspace retains the catalog base used for comparison.
Local edits create another version rather than rewriting past observations.

The shared editor separates definition, group organization and feedback mode.
The [author guide](./writing-practices.mdx) owns definition controls.
Feedback mode belongs to the workspace, not to the catalog's review standard.

## Review an update

An update compares your current definition, its base and the offered definition.
Select current or offered content for each changed field.
A conflict means both sides changed the field.
Accepting selected content creates a new version.

Declining keeps local content and advances the catalog base.
It does not permanently hide later offers.
Reset replaces local customization with the current catalog definition.
The interface shows the concrete difference before the reset.

## Practice versions

Earlier observations retain the practice version used to judge them.
Name, group and guidance edits do not change the review standard digest.
The exact version still forms part of scan reuse identity.
A changed script or source contract arrives through a new active version.

An unchanged bundled script can receive its audited catalog update.
A changed copy retains its text until an admin accepts an update or rewrites it.
For the practice model cutover, follow the [operator migration guide](https://github.com/hephaestus-build/Hephaestus/blob/main/MIGRATION.md) before you change scripts.
A script that no longer meets the contract stops with a recorded reason.
It never falls back silently to the built-in script.
