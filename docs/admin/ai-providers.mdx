title: Connect an AI provider
description: Register an AI provider and its models for the instance, price them, and share them with workspaces.

Hephaestus ships with no AI provider, model, or key.
Practice reviews and conversations stay inactive until a workspace assigns an active, priced model.
Use this procedure to connect a provider for the whole instance and share its models with workspaces.
A workspace can also connect its own provider, as [AI models and spending](/user/ai-models#connect-your-own-provider) describes.

## Before you start

- You need the instance admin role and a recent sign-in.
- Get an API key for the provider account that pays for the shared models.
- For an endpoint on your own network, first allow it in the chart. [Admit a model endpoint on a private network](./private-network#admit-a-model-endpoint-on-a-private-network) gives the steps.

## Connect the provider {/*#1-the-staged-flow-and-why-it-is-staged*/}

A new connection and a new model start inactive.
A model can become active only after its connection is active and its price is set.

1. Open **Instance administration → AI models**.
2. Select **Add connection**.
3. Enter a **Display name**.
4. In **Endpoint preset**, choose the provider. The preset fills **API** and **Base URL**, as [Presets](#presets) lists.
5. Check **Base URL**. For **Azure OpenAI v1**, replace `RESOURCE` with your Azure resource name.
6. Enter the **API key**.
7. Optional: in **Service receiving requests**, choose the service that receives the requests, such as Azure or a gateway.
8. Select **Test and fetch models**. The result says **Reachable** and the number of models found.
9. Select **Add connection**.

**Base URL**, **API**, and the authentication cannot change after you save.
To move to another endpoint, add a connection, test it, point the assignments to its models, and turn off the old one.

## Add and price a model {/*#4-pricing-a-model*/}

1. Select **Add model** on the connection.
2. Enter the **Upstream model ID**. The test fills the suggestions.
3. Enter a **Display name** that developers can read.
4. Under **Price**, choose **Price per 1M tokens**, and enter **Input (USD)** and **Output (USD)**.
5. If your provider reports cache tokens, also enter **Cache read (USD)** and **Cache write (USD)**.
6. Under **Data handling**, choose **Operated by**: **Your organization** or **A provider**.
7. Optional: in **Note for admins**, record the region, the agreement, and its renewal date.
8. Under **Initial workspace access**, choose **All workspaces** or **Selected workspaces**.
9. Select **Add model**.

Hephaestus never infers a price, because rates differ by contract and region.
For a model without per-token charges, choose **No metered API cost** and give the reason.
If a call reports tokens for a rate that you left empty, the whole call has no price.
Reasoning tokens count as output tokens and have no rate of their own.

**Operated by** sets the tier that members see.
Choose it as [Data handling and AI choices](/user/ai-models#data-handling-and-ai-choices) describes.

A new price replaces the old one from that moment.
Past usage keeps the rates that it was charged at.

## Activate and share the model {/*#5-sharing-an-instance-model*/}

1. Turn on **Active** for the connection.
2. Edit the model, turn on **Active**, and select **Save changes**.
3. Optional: to change who can use the model, select its **Workspace access**. In **Who can use this model**, choose **All workspaces** or **Selected workspaces**, and select **Save access**.

A workspace admin then assigns the model, as [Assign models](/user/ai-models#assign-models) describes.
[Shared models and your own provider](/user/ai-models#shared-models-and-your-own-provider) lists what the workspace sees of the model.

A reduced workspace access or a turned-off connection stops every assignment to the model at once.
The assignment stays and reads **Not ready**.

## Control workspace providers

Under **Settings** on **AI models**:

- **Let workspaces add providers and models** lets workspace admins connect their own provider. It is on by default. Turning it off blocks new connections and models. Existing ones stay manageable.
- **Allowed provider hosts** limits the hosts that a connection can use. Empty allows any public host.

## Check that it worked

1. As a workspace admin, open the workspace's **Administration → AI models** page.
2. Assign the model to **Practice reviews**. The assignment does not read **Not ready**.
3. Request a review of eligible work, as [Practice reviews and feedback mode](/user/practice-reviews#request-a-review) describes.
4. Check that the review does not record **No AI model is assigned to practice review.**

## Rotate the API key

1. Open the connection with **Edit connection**.
2. Enter the new key in **API key**.
3. Select **Test changes**.
4. Select **Save changes**.

Leave **API key** blank to keep the stored key.
To delete the stored key, select **Remove stored API key**.

## Replace a model {/*#replace-an-unavailable-model*/}

When a provider withdraws a model, add its replacement before you remove it.

1. Add the replacement, price it, declare its data handling, and make it active.
2. Ask each workspace admin to assign it where the old model was assigned, as [Replace a model](/user/ai-models#replace-a-model) describes.
3. Turn off the old model.

Do not change the old model's upstream ID to the new one, because past usage must keep its model.
A model that a workspace still assigns cannot be deleted.

## Undo

1. Turn off **Active** for the model, or for the connection.
2. To remove them, delete the models first, then the connection.

Turning a model off stops new work on it at once, in every workspace.

## Reference

### Presets

The preset fills the create form only. A saved connection does not keep it.

| Preset | **Base URL** | **API** | Key header |
| --- | --- | --- | --- |
| **OpenAI** | `https://api.openai.com/v1` | **Responses API** | Bearer token |
| **Azure OpenAI v1** | `https://RESOURCE.openai.azure.com/openai/v1` | **Responses API** | `api-key` header |
| **Anthropic** | `https://api.anthropic.com`, without `/v1` | **Messages API (Anthropic)** | `x-api-key` header |
| **Other endpoint** | Empty | Your choice | Your choice in **Authentication** |

Prefer **Responses API** for reviews and conversations, because they call tools across many turns.
Choose **Chat Completions API** only if the endpoint does not serve the Responses API.
The Anthropic preset serves reviews, feedback, and conversations. It does not support Bedrock or Google Cloud authentication.

### Model limits

Each model has a **Context window** and **Max output tokens**.
Hephaestus uses your value first, then the value that the provider reports, then a shipped value for OpenAI models.
Without a reported output limit, it uses a quarter of the context window, at most 16,384 tokens.

The provider reports limits for Anthropic, OpenRouter, vLLM, LiteLLM, and Ollama.
OpenAI and Azure OpenAI report none. For an Azure deployment, set both values yourself.
A test of a saved connection, and a server start, read the reported limits.

A model without an output limit cannot run, and **AI models** marks it **Limits missing**.
A conversation model needs a context window of at least 32,768 tokens and an output limit of at least 4,096 tokens.

### Output limit

Every chat call has an output limit: the model's **Max output tokens**.
The proxy lowers a larger limit in a request to it, and adds it when the request names none.
The output limit and the request size give the upper bound of a call, as [Workspace budgets and alerting](#workspace-budgets-and-alerting) describes.
A server that ignores the limit can write more and cost more than that bound.

### Instance-wide LLM settings

Chart values never set a provider, a model, a price, or a credential.
You enter those on **AI models**, and every server uses the same catalog.
Each sandbox reaches a provider only through the LLM proxy of its server, so no sandbox receives a provider key.
A workspace's change of a model assignment applies to the next conversation turn, without a restart.

These chart values hold deployment facts:

| Value | Default | What it does |
| --- | --- | --- |
| `config.llmDisplayCurrency` | Empty | Set `EUR` to show converted spend beside USD. It changes the display only. Any other value stops startup. |
| `config.llmPrivateHosts` | Empty | Model endpoints on your own network, as [Rules for the private host lists](./private-network#rules-for-the-private-host-lists) describes. |
| `config.llmPrivateHostsAllowHttp` | `false` | Accepts `http://` base URLs for the hosts in `config.llmPrivateHosts`. Every other host still needs HTTPS. |

### Workspace budgets and alerting

Each workspace has two monthly budgets for each UTC calendar month. They are never added together:

- **Shared-model budget**: caps the workspace's spend on the models that you share, which your provider account pays for. Set it in **Instance administration → AI usage** with **Set budget** or **Change budget** on the workspace's row.
- **Provider cap**: caps the workspace's spend on its own provider. A workspace admin sets it, as [Set a cap on your own provider](/user/ai-models#set-a-cap-on-your-own-provider) describes.

Both are uncapped by default, and **Remove cap** clears one.
To stop shared-model spend in the middle of a month, set the budget to $0.
To stop all AI work of a workspace, turn off its practice reviews and conversation models, not its budget.

When a budget is reached, its work pauses, as [Set a cap on your own provider](/user/ai-models#set-a-cap-on-your-own-provider) describes.
The pause shows on the workspace's **AI usage** and **AI models** pages.
Developers can see a reached cap and report it, so plan for support requests.

A cap counts each running call at its upper bound until its usage is measured.
The upper bound comes from the request size, the [output limit](#output-limit), and the rates of the model.
Calls that start at the same moment can pass a cap by their upper bounds.
A server that ignores the output limit can pass it by more.
Hephaestus never estimates tokens or charges.

#### Unpriced and unmeasured usage {/*#missing-prices-and-unverified-measurements*/}

A call of a model without a price, or without a rate that the call uses, has no cost and no upper bound.
The **AI usage** pages show it as **Unavailable cost**, and the spend that they show is a lower bound.
Such a call pauses a capped budget, as [Set a cap on your own provider](/user/ai-models#set-a-cap-on-your-own-provider) describes.
Adding a missing rate later does not give a cost to a past call.
Do not edit the database to clear a pause.

A call whose usage Hephaestus cannot measure counts at its upper bound, and the month stays verifiable.

#### Alerts

Hephaestus sends no notification when a workspace reaches a cap.
`HephaestusBudgetExhausted` and `HephaestusBudgetBlocked` in [Alerts](./alert-rules.md#alerts) watch the budgets, and [Metrics](./metrics.md) lists the usage counters.
Each pause also logs a warning.

### Provider capacity {/*#6-sharing-provider-capacity*/}

Each model has a call pool that learns how many calls in flight the provider serves, across all servers and workspaces.
When the provider refuses calls or slows down, every caller of that model waits.
[Call pools](./runtime-roles.mdx#call-pools) explains how the limit changes.

The instance admin API reads the pools:

- `GET /api/admin/llm/call-pools` lists the pools with their IDs.
- `GET /api/admin/llm/call-pools/models` lists the models with their pools.

No supported interface changes a pool or puts models into one pool.

### Test model tool choice

**Test tool choice** on a saved model sends two short synthetic requests, which the provider can charge for.
The result says whether reviews can require the model to submit its result through a tool.
The result saves at once, without **Save changes**.
The test is not offered for **Messages API (Anthropic)** models, which always let the model decide.
Repeat it after the provider changes the model behind an alias.

### Reasoning effort

**Reasoning effort**, under **Advanced** in the model form, sets how hard a reasoning model thinks on each call.
**Provider default** sends no value. Use it for a model that does not reason, because the provider can reject the value.
A level that the model does not accept fails the call.

## Troubleshooting

### Test and fetch models fails

| Result | Cause and fix |
| --- | --- |
| HTTP 401 or 403 | The key is wrong, expired, or lacks permission. Enter the key again. |
| HTTP 404 | The base URL lacks `/v1` or has an extra path segment. Add a connection with the correct URL. |
| HTTP 3xx | The test does not follow redirects. Enter the URL that the provider serves from. |
| Hephaestus could not reach the provider | DNS, TLS, a 5-second timeout, or the address check failed. Check the host from the server, not from your computer. |
| The provider's response was too large | The endpoint is not an OpenAI-compatible model list. |

A failed test blocks nothing. You can save the connection and enter the model ID by hand.
For a host on your private list, the test shows no cause. The server log has it.

### Answers arrive all at once, or fail after 2 minutes

A proxy between Hephaestus and the model buffers the answer.
The server fails a conversation call whose stream sends nothing for 2 minutes.

1. For nginx, set `proxy_buffering off` on the completions path.
2. For other gateways, turn off response buffering for `text/event-stream`.

### A model thinks on every call {/*#models-that-think-by-default*/}

Some model servers make a model think unless the request turns thinking off with a field of their own, such as Qwen3 on vLLM.
Hephaestus sends only the standard reasoning effort, so **None** does not turn that thinking off.
The model can spend its whole output limit on thinking, and the turn fails.

1. Set the default chat template arguments of the model server so that `enable_thinking` is `false`.
2. Restart the model server.
