This page lists what an operator can see and change about practice review on an instance that runs on the Helm chart.
The values come from the chart's `values.yaml` and the server's `application.yml`.
Workspace admins choose coverage, models and feedback mode in the web app, as [Practice review](./practice-review.mdx) describes.

## Chart values

These chart values change how practice review runs.
[Helm chart reference](./helm-chart) gives the defaults and the other values.

| Value | Effect on practice review |
| --- | --- |
| `sandbox.enabled` | Turns the review runtime on. Without it, the server runs no practice review and no conversation turn. |
| `sandbox.reviewMemory` | The memory that the sandbox nodes give review Pods. The number of reviews that run at once is this value divided by the request of one review sandbox. [Sandbox sizes](./sandboxes#sandbox-sizes) gives the calculation. |
| `sandbox.templates.review.resources` | The requests and limits of each review sandbox Pod. |
| `sandbox.gateway.maxConnections` | The connections that the server's sandbox gateway holds open. A review holds about 54, and 170 at most. |
| `server.gitCache.sizeLimit` | The size of the volume that holds repository mirrors and attempt folders on each server. |
| `server.drainTimeoutSeconds` | How long a stopping server finishes its running reviews. A review that still runs at the end stops and runs again. |

Reviews run as sandbox Pods in the sandbox namespace (`sandbox.namespace`).
The chart's NetworkPolicies let a sandbox reach only the gateway port of the servers: no DNS, no Kubernetes API and no database.
Model calls and source reads go through that gateway.
[Sandboxes](./sandboxes) gives the prerequisites and the templates.

## Fixed settings

The chart has no value for these settings.
Each one explains a review that starts late, is refused, or stops early.

| Setting | Fixed value |
| --- | --- |
| Quiet window | 2 minutes after the newest event, and at most 10 minutes after the first event |
| Reviews that one person can request by hand | 5 for each workspace in one hour |
| Model calls for each practice | 36 |
| Output tokens for each practice | 48,000 |
| Model use of one review attempt | Twice the sum of its practices' budgets. Past it, the model proxy refuses the next call with `403`. |
| Attempts of a review after a retryable failure | 5 |

The timeout of the workspace's **Practice reviews** model assignment limits the whole review run.
A workspace admin sets it on the **AI models** page.
A workspace admin can also change two defaults for the workspace.
**Review settings → How reviews start → Time between reviews (minutes)** is 15 by default.
**Sending feedback → Post feedback after merge** is off by default.

### Quiet window

Events on the same work wait in one quiet window, so that one review covers a burst of pushes and edits.
A merge, a close, a submitted pull request review, a closed or deleted issue, and an archived document do not wait.

The item event records why an event waits or does not start a review:

| Reason | Meaning |
| --- | --- |
| `QUIET_WINDOW` | The window is open. When it closes, one review runs at the newest event. |
| `COALESCED` | A newer event of the same window started the review. |
| `REVIEW_IN_PROGRESS` | An earlier review of the same work still measures a practice that the event selects. |
| `CHECKS_PENDING`, `CHECKS_AWAITING_APPROVAL`, `NO_CHECKS_REPORTED` | A practice needs the work's checks, and the checks have not finished. The next event on the work selects the practice again. |
| `ALREADY_CURRENT` | Each practice that the event selects already has a current observation. |

[Select a review](/contributor/practice-review-pipeline#select-a-review) explains the selection.

### Temporary evidence on the server {/*#temporary-evidence-and-restarts*/}

Each server keeps its copies of reviewed work under `/data/git-repos`.
The copies are a cache. A missing mirror is cloned again on the next sync or review.

| Copy | Location below `/data/git-repos` | Removal |
| --- | --- | --- |
| Capture spools and context snapshots | `.evidence-spool/<workspaceId>/` | When the capture closes. The server retries a failed removal. |
| Repository mirrors and checkout caches | The mirror of each repository and its `hephaestus-checkouts` directory | When the workspace stops monitoring the repository, or when the cache is full |
| Attempt inputs and input archives | `jobs/<workspaceId>/<jobId>/` | One hour after the attempt ends, and at startup |

At startup, the server removes abandoned spool copies before it admits work.
If it cannot read a directory or remove a copy, it logs `event.name=evidence.spool.cleanup.failed` and does not start.
Treat the volume as sensitive storage.
[Temporary copy custody](/contributor/practice-review-pipeline#temporary-copy-custody) explains the ownership of each copy.

## Running instance

A server is ready when it can serve its API.
Readiness does not include practice review, so a ready server can still run no reviews.

### Review health

An authorized request to `/actuator/health` on the [management listener](./monitoring.md#scrape-metrics) shows the `practiceReview` component:

| Status | Detail | Meaning |
| --- | --- | --- |
| `UP` | `reviewsEnabled=false` | `sandbox.enabled` is false. The server runs no reviews. |
| `UP` | `reviewsEnabled=true` | The server can run reviews. |
| `OUT_OF_SERVICE` | `reason=SOURCE_AUTHORIZATION_EXPIRED` | A source-use decision for automated practice review has expired. [Source governance](./dsms/item-source-governance.md) describes these decisions. |
| `OUT_OF_SERVICE` | `reason=GIT_CHECKOUT_DISABLED` | Repository checkout is off. The chart always turns it on, so this status does not occur on the chart. |

A workspace without a model for practice review does not change the server's health.
Its reviews show the refusal under **Practices → Practice reviews → Reviews**, and `practice.review.refused` counts it.

### Queue health

The server exports these meters.
[Metrics](./metrics.md) gives the Prometheus names, and [Alert rules](./alert-rules.md) gives the rules that read them.

| Meter | Meaning |
| --- | --- |
| `agent.run.oldest_due_age_seconds` | By `kind` and `band`: the time since the oldest due run became due. A due run is queued, has no hold, and its `available_at` has passed. `0` when no run is due. Growth that continues means that the reviews have no capacity. |
| `agent.run.due` | By `kind` and `band`: queued runs that can start now. |
| `agent.run.runs` | Runs that have not ended, by `kind`, `band`, `state` (`queued` or `leased`) and `hold_reason` (`none`, `budget` or `sandbox_room`). `state="queued",hold_reason="budget"` separates a workspace that spent its budget from an idle instance. |
| `agent.run.sampler.failure` | Samples that failed. The gauges then keep their last values. |
| `agent.run.claim.wait` | By `kind` and `band`: the time from a run's `available_at` to its claim. A run that returns to the queue waits again from its new `available_at`. |
| `agent.job.infra.retry.requeued` | Attempts that run again after a retryable failure, by `cause`: `preparation`, `sandbox`, `server_unreachable` or `provider_unreachable`. |
| `agent.run.reaped` | Runs that the server took back. `kind=review,outcome=attempts_exhausted` counts reviews that failed because each attempt's holder stopped. |
| `agent.job.composition.stopped` | Destinations whose feedback the server did not write, by `cause` and `outcome`. |
| `agent.job.retention.stripped`, `agent.job.retention.deleted` | Rows that the retention sweep pruned. |
| `llm.budget.exhausted`, `llm.budget.blocked` | A crossed budget cap, and work that a cap refused. `surface="model_call"` counts model calls of a running job that the model proxy refused. |
| `practice.review.refused` | Refused reviews, by `phase` (`submission` or `execution`) and `reason`. |
| `agent.review.practice_scripts` | One count for each practice in the report of a review attempt, by `status`: `ok`, `withheld`, `failed`, `not_reached` or `not_finished`. |

A growing share of `failed`, `not_reached` or `not_finished` in `agent.review.practice_scripts` means that scripts stop before they return a result.

## Why practice scripts stop early {/*#the-trace-line*/}

Each practice of a review runs one script: its practice script, or the built-in review.
The review's sheet under **Practice reviews → Reviews** has one trace line for each practice that ran a script.
The line starts with how the script ended:

| The line starts with | Meaning | Fix |
| --- | --- | --- |
| **… returned a candidate observation** | The script returned a valid candidate observation. Admission can still withhold it. | None. |
| **… stopped without a candidate observation** | The script stopped, for the reason that the line gives, such as `it raised an error` or `it ran out of time`. | For an error, select **Edit the script**, and [test the script locally](./practice-scripts.mdx#test-a-script-locally). For time or budget, see below. |
| **The review ended before … started** | The attempt ran out of time or budget, or was cancelled, before it reached this practice. | See below. |
| **… did not finish** | The review's report does not name the script, for example because the sandbox stopped. | See below. If it continues, read the sandbox log that the job keeps. |

The practices of a review share the timeout of the **Practice reviews** assignment.
If many practices of one review run out of time, raise that timeout on the **AI models** page.
Otherwise, make the slow script faster.
[Limits](./practice-scripts.mdx#limits) gives the limits of a script.

A script that fails, is withheld or is not reached gives its practice no result in that review.
It is not a claim about the developer's work.
[Admission reasons](/contributor/practice-review-glossary#admission-reasons) defines the reasons that admission records.

## Fixed limits

- **Repository capture.**
  A capture holds every file at the reviewed commit and the Git history that it can reach.
  A checkout with its mirrored history over 8 GiB refuses the whole repository.
  The server never captures a smaller tree.
  Submodules are not fetched, and Git LFS files stay pointers.
  Size the Git cache volume for the repositories that the workspaces monitor.
- **Outline documents.**
  A review reads the documents linked from the work, then a few more that a search finds.
  A conversation answer reads at most 15 documents, and at most 4,000 characters of each.
- **Deleted work.**
  When reconciliation finds that work is gone at the provider, a review of it stops without a result.
  If the work comes back, the next sync clears the mark.
- **Prompts.**
  The prompts ship with the release. No screen changes them.

[Data retention](./data-retention) gives how long jobs, item events, results and usage records stay.
[Scans](./practice-scans.mdx) gives the limits of a scan.
