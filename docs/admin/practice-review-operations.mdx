# Practice review operations

Use this reference to configure the runtime and monitor a deployed instance. Workspace administrators
should start with [Practice Review](./practice-review.mdx).

## Deployment configuration

Server configuration metadata defines property names, types, and defaults; the reference Compose files
define which environment variables reach the application.

A working deployment must:

- enable the agent runtime on both the submitting server and claiming worker;
- enable `GIT_CHECKOUT_ENABLED` for repository access and give every server and worker container its
  own storage under `HEPHAESTUS_FABRIC_ROOT` for repository mirrors and attempt inputs; enabling agent
  execution alone does not enable repository collection;
- set campaign, request-rate, retry, and retention limits appropriate to its budget and governance policy.

Each workspace enables practice review and chooses its own coverage.

`PRACTICE_REVIEW_SAMPLING_TEMPERATURE` sets the sampling temperature for practice-review
model calls, not mentor calls. If unset, the provider default applies. Use a value supported by the
selected model and confirm that your deployment forwards the setting. A low temperature does not
guarantee repeatable judgments; evaluate changes against representative cases.

See the
[server configuration](https://github.com/hephaestus-build/Hephaestus/blob/main/server/application/src/main/resources/application.yml)
and [reference Compose files](https://github.com/hephaestus-build/Hephaestus/tree/main/docker) before changing an
environment variable. Unknown or unforwarded variables do not configure the application.

Repository mirrors and attempt folders are disposable container-local storage, not a shared evidence
store. Each container keeps bare mirrors under its own `HEPHAESTUS_FABRIC_ROOT` (`/data/git-repos` by
default; the shipped Compose files mount the `git-repos` volume into the server and `worker-git-repos`
into the worker) and clones a missing mirror again on the next sync or review. Git runs in-process
through JGit, so no `git` binary and no second image are involved: commit ingestion runs on the server
role against the server's mirrors, review preparation on the worker role against the worker's, and a
server whose worker role is enabled uses its one root for both. Attempt folders live under the same
root. Sandbox inputs and results travel through the authenticated worker gateway.
PostgreSQL retains admitted observations and their citation verification results; delivery does not
require the worker's source files. The storage and cleanup contract is defined in
[ADR 0041](https://github.com/hephaestus-build/Hephaestus/blob/main/docs/decisions/0041-compose-1x-kubernetes-2.md#evidence-admission-and-deletion).

Source authorization is not a deployment toggle. The shipped artifact-source contract fixes which governed
sources each purpose may use; integrations only determine which authorized sources are available. See
[Artifact-source governance](./dsms/artifact-source-governance.md).

## Running instance

### Queue health

The job queue exposes its own signals — alert off these rather than reading application logs.

- **`agent.queue.oldest_age_seconds`** — age of the oldest eligible queued job, `0` when empty.
  Alert on sustained growth: queue depth alone does not distinguish a transient burst from persistent backlog.
- **`agent.queue.depth`** — queued jobs eligible to run now.
- **`agent.queue.held`** — jobs parked on an exhausted budget.
- **`agent.queue.running`** — jobs running fleet-wide.
- **`agent.queue.health.sampler.failures`** — failed samples; the gauges keep their last-good value rather
  than reporting a false empty queue.
- **`agent.job.claim.latency`** — time between a job becoming eligible and being claimed.
- **`agent.job.execution.duration`** — tagged by `jobType` and outcome `status`.
- **`agent.job.delivery.recovered`** — deliveries stuck by an executor crash and successfully re-attempted.
- **`agent.job.retention.stripped`** / **`agent.job.retention.deleted`** — rows pruned by the retention
  sweep.
- **`llm.budget.exhausted`** / **`llm.budget.blocked`** — a cap crossed, and work refused at a cap.
- **`practice.review.occasions`** — live issue-update recording attempts, tagged by `signal` and
  `outcome` (`deferred` or `duplicate`). Opening and closing are not included.
- **`practice.review.refused`** — refused reviews, tagged by `phase` (`submission` or `execution`) and
  `reason`. Submission reason `coalesced` counts displaced issue-update snapshots, not review failures.
  These counters measure attempts, including rolled-back transactions; inspect the occasion trace for
  committed outcomes.
- **`practice.feedback.dispatch`** — durable-dispatch outcomes, tagged by bounded `destination` and
  `state`. Alert on sustained `UNCERTAIN` or `FAILED` outcomes. `UNCERTAIN` means delivery is not yet
  confirmed; `FAILED` is terminal after the retry limit or an unrecoverable dispatch record.

Query `/actuator/health/readiness` for aggregate readiness. An authorized response includes the
**`practiceReview`** component. An enabled review worker reports `OUT_OF_SERVICE` with
`GIT_CHECKOUT_DISABLED` when repository checkout is disabled, or `SOURCE_AUTHORIZATION_EXPIRED` when an
automated-review source authorization has expired. Missing model bindings are workspace-specific and remain
visible in **Review activity** and the refusal counter; they do not remove the worker from service.

Gauges are sampled periodically; timers and counters are recorded when the corresponding event occurs.
Metric names in the instrumented code are the source of truth for dashboards and alerts.

### Issue-update queue

Live issue updates become eligible 30 seconds after the last newly queued snapshot, or when the oldest
reaches five minutes. The server checks every five seconds, handling at most 100 issues per sweep.
Opening and closing are separate occasions and do not wait in this queue.

Returning to an already-pending snapshot does not reset eligibility. Queue load, contention and failures
can delay submission beyond eligibility. Job-queue gauges exclude these pre-submission occasions.

### Log correlation

The application emits one JSON object per log line, so worker logs filter by the correlation keys
under `mdc` with the tools already in the shipped Compose stack. From the directory you deploy from:

```bash
# All log lines for one agent job
docker compose logs --no-log-prefix application-worker \
  | jq -cR 'fromjson? | select(.mdc."job.id" == "<job-uuid>")'

# All errors for one workspace
docker compose logs --no-log-prefix application-worker \
  | jq -cR 'fromjson? | select(.mdc."workspace.id" == "<workspace-id>" and .level == "ERROR")'
```

A deployment that ships logs to its own collector can key dashboards and alerts on the same `mdc`
fields; label names there are deployment-specific.

**Retention.** Terminal job payloads are stripped before their rows are deleted, so row retention shorter
than payload retention is incoherent — the application refuses to start rather than accept it. Treat the
fabric root as sensitive storage. Delivery-policy evaluations and dispatch intents follow their owning
review ledger. Disconnect, person erasure, and workspace purge remove their matching copies. Once a sent
or withheld dispatch has been projected into that ledger, its duplicate summary and inline-comment payload
is erased while the destination key and provider references remain as the idempotency record. A failed
dispatch keeps its package because an administrator can still retry it. Selected coverage targets follow
their workspace membership or monitored repository.

**Dispatch recovery.** One dispatch owns the exact summary and inline comments in a review. Before each
provider create, it reconciles the stable marker or recurrence key already stored with the provider. A
found placement is preserved, a definitive not-found permits the first write, and an inconclusive lookup
leaves the package `UNCERTAIN` rather than risking a duplicate. The dispatch becomes `SENT` only after the
whole package converges.

Two consequences to plan for:

- **Sustained `UNCERTAIN` means Hephaestus cannot prove whether the provider accepted the write**, not that
  feedback is queued. Fix provider connectivity or credentials so reconciliation can continue.
- **A dispatch interrupted mid-write can outlive its retry budget without reaching `FAILED`.** It is
  deliberately not failed, because one of its provider objects may be live, and remains uncertain until
  provider lookup can confirm the outcome.

Do not repair an `UNCERTAIN` dispatch by editing its row. Restore provider lookup instead; the state, write
fence, retry count, and lease together prevent duplicate provider writes.

## Limits you should know about

Configuration metadata describes deployment settings; the artifact-source catalog defines capture semantics.
These behaviors matter independently of configured capacity:

- **Background task cadences are fixed in code.** Their thresholds may be configurable even when their
  polling schedules are not.
- **Feedback preparation recovery has a bounded window.** The sweeper selects recent completed pull
  request and issue reviews with missing preparation marks. Older unfinished preparation is not
  automatically recovered. A successful empty result is complete; recovery does not rerun the model.
- **Retryable occurrences eventually lapse.** A workspace left misconfigured can accumulate retries and
  then go quiet when their deadline passes.
- **Nothing is ever deleted from the occurrence ledger**, in any state, including retired rows. It is the
  record of what was *not* done, and it only grows. Size it accordingly on a busy instance.
- **Repository capture includes every regular and executable file at the reviewed commit**, including
  binary content and large files, plus sanitized Git history reachable from the reviewed commit and
  the mirrored branches and tags. Native bash, Git, ripgrep, and file-discovery tools are available.
  File count and content size do not truncate the tree. Symbolic links are materialized as regular
  files containing the link target, without following it. Submodules are not hydrated; their
  presence, like an excluded unsafe path, is reported as a partial capture, and a snapshot entry that
  is not a regular file or directory fails the capture. Git LFS pointers are captured as committed,
  not replaced by downloads. Provision storage for the mirror, captured content, and per-job staging;
  model-facing output limits do not bound capture storage. The captured worktree and Git metadata are
  read-only, with no repository credentials or upstream configuration. Reviews use an isolated
  internal Docker network; the authenticated worker gateway must be reachable on that network.
- **Repository preparation is bounded per snapshot and per walk.** Server and worker roles use
  JGit for capture. This work needs no sandbox admission and does not count against
  `SANDBOX_MAX_CONCURRENT`; `GIT_MAX_CONCURRENT_INGESTIONS` (default 2) caps how many captured
  commits a container writes to PostgreSQL at once. A repository whose checkout plus mirrored history
  exceeds `GIT_MAX_SNAPSHOT_BYTES` (8 GiB by default) is refused whole, measured before the snapshot is
  written; raise it for larger monorepos. Refusal fails the operation; it never selects a smaller
  tree. The mirror itself is not measured, so size the fabric root for the repositories you monitor.
  A commit-history walk reads commits in pages of 256 and pauses after 32 pages that needed
  capture — pages whose commits were all captured before do not count — and the next sync cycle
  resumes from the commits already captured.
- **Linked Outline documents are retrieval-limited, and the mentor and review paths do not agree.** A
  review resolves documents *linked from* the work first and only tops up a small number by search; the
  mentor searches the whole corpus and truncates each document. Neither path can report that it found
  everything, and neither is a substitute for the other when you are diagnosing missing context.
- **Work that has been deleted at the provider yields a review with no evidence, not an empty one.**
  Once a reconciliation pass finds work missing upstream, evidence capture reports its sources as
  unavailable and the review stops without recording anything about that work. If the work reappears,
  the next ordinary sync clears the mark and a later review reads it again.
- **No screen edits what the model is told.** What Hephaestus observes is shaped by each practice's
  criteria; the wording it then chooses is shaped by a prompt that ships with the release. Changing the
  latter is a code change.
