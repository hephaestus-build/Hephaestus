This page is for workspace admins. Instance operators configure provider apps and deployment settings
in [Integrations and reference deployment](./production-setup). Account linking belongs in
[User settings](/user/user-settings).

## GitHub

[GitHub integration](./github-integration) owns app setup and permissions.
Removal of a monitored repository erases its mirror, not the upstream repository.

1. Install the GitHub App for the organization or use a personal access token connection.
2. For an App connection, manage repository access in the GitHub installation.
3. For a token-managed connection, open **Administration → Integrations → GitHub → Manage repositories → Add a repository**.

## GitLab

A deployment syncs one GitLab instance. **Create workspace** lets an eligible user select a group on
that configured instance, using their linked GitLab account and an access token. A login provider
for a different instance permits sign-in, but does not permit a workspace there.

Hephaestus automatically registers group hooks with a signed routing token bound to the connection.
Do not replace that token with `WEBHOOK_SECRET`.

1. Open **Administration → Integrations → GitLab → Manage repositories → Add a repository**.
2. Add the project by its full namespace path.

The connection shows token expiry. Hephaestus checks the token each day and rotates it before expiry
when GitLab permits it. If it cannot rotate the token, use **Personal access token → Replace token**.
This keeps repositories and stored work. Optional connection-alert emails report problems and recovery.

GitLab reconciliation removes deleted issue and merge-request notes, including diff notes.
Removal requires a complete listing and a direct check that each missing note is gone.
An incomplete listing removes nothing for that parent.
Do not expect every deletion to arrive as a webhook.

## Slack

Members must separately link their Slack accounts to use Heph in direct messages.
Monitoring starts after a visible announcement is posted.

1. Open **Administration → Integrations → Slack**.
2. Connect the Slack workspace through OAuth.
3. Use the channel picker to add channels for monitoring.

Channel monitoring and a member's permission to use their messages are separate:
[User settings → Slack](/user/user-settings#slack) lets members control their new channel messages.
The workspace connection does not override a member's AI choice.

Use **Reconnect Slack** with the same Slack workspace to replace a bot token without removing
channels, their consent, mirrored messages, or retention settings. Do not use **Disconnect** for this.

## Outline

Hephaestus reads the selected collections.
It does not write documents to Outline.
Members can link their own Outline accounts to attribute authored documents.
A workspace admin cannot approve a new Outline operator through its URL.

1. Open **Administration → Integrations → Outline**.
2. Enter an operator-approved HTTPS origin and an API key.
3. Register the collections to mirror.

### Replace an Outline key without erasing the mirror

The current UI has no key-replacement form for an existing connection.
**Disconnect** erases the mirror.

:::caution CAUTION: Outline key secrecy and connection identity
Keep the key out of shell history, logs, and support tickets.
Use the same origin and a key that belongs to the same Outline team.
Do not change the origin or team during key rotation.
:::

1. To keep the mirror, create a valid API key in Outline.
2. As a workspace admin, send this authenticated request to the application server's existing connection API with normal CSRF protection:

   ```http
   POST /api/workspaces/{workspaceSlug}/connections
   Content-Type: application/json

   {
     "kind": "OUTLINE",
     "userInput": {
       "server_url": "https://wiki.example.com",
       "token": "<new API key>"
     }
   }
   ```

3. Check that the response's connection ID matches the existing connection.
4. Check webhook registration.
5. Use **Sync now** to verify that collections refresh.
6. Revoke the old key only after that check succeeds.

The API validates the key and updates the connection's credentials without deletion of documents or collection registrations.
It resets connection configuration, including subscription metadata.

## Read sync errors

A healthy connection does not prove that every resource synced.
An error clears only when its affected sync path succeeds.
A skipped pass keeps the error.

1. For repositories, open **Administration → Integrations → GitHub/GitLab → Manage repositories**.
2. For Slack channels or Outline collections, open that integration's page.
3. Open its resource sync table.
4. Read the affected resource's last error.
5. Correct access or configuration.
6. Select **Sync now** on the connection.

A repository reported as **Repository not found or not accessible** may have moved or lost access.
The mirror stays. After two consecutive unavailable responses, automatic rechecks run at most once
in 24 hours. **Sync now** checks immediately. See
[Unavailable repositories](/user/workspace#unavailable-repositories).

## Disconnect is an erase

**Disconnect** permanently erases the integration's mirrored data in this workspace before it attempts
provider cleanup. Reconnecting does not restore that data.

- GitHub and GitLab: repository mirrors and their associated synced work.
- Slack: mirrored messages, threads, channel records, and associated consent records.
- Outline: mirrored documents, collection registrations, and document events.

The upstream repositories, messages, and documents remain.
Provider cleanup is best effort.
If local erasure fails, the connection remains unchanged.

1. Inspect provider-side app access, hooks, and keys separately.
2. To repair a credential, use the replacement paths above or [Credential key rotation](./credential-key-rotation), not Disconnect.
