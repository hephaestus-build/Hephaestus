title: Troubleshooting
description: Identify and recover from failures in a self-hosted Helm deployment.
---

Start with [Kubernetes troubleshooting](./kubernetes#troubleshooting).
Inspect the affected Pod's events and logs in the deployment namespace.
Do not print Secret objects or credentials while collecting diagnostics.

## Startup and sign-in

| Symptom                                                       | Check and recovery                                                                                                                                                                              |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Startup fails at `ProxyTrustGuard`.                           | Set `trustedProxies` to the real ingress addresses. [Gateway routes](./kubernetes#gateway-routes) gives the requirements.                                                                       |
| Startup reports an encryption-key error.                      | Restore the original key for an existing database. Do not generate a replacement key for data encrypted with the old one. [Secret custody](./secret-custody) owns key recovery.                 |
| The login page has no sign-in button.                         | Configure a complete GitHub or GitLab login provider. [First steps](./first-steps#1-configure-a-login-provider) owns the initial setup. Change an existing provider in instance administration. |
| Sign-in succeeds but the user is not an admin.                | Check `config.auth.bootstrapAdmins` against the provider's stable account identifier. [Instance admin](./instance-admin#bootstrap-and-recovery) owns recovery.                                  |
| Helm reports `failed` or a Pod waits for a pending changeset. | Check the migration Job. A Helm failure does not prove that the Job stopped. Follow [Recover a stopped cutover](./pull-based-deployment#recover-a-stopped-cutover).                             |
| The browser reports a certificate error.                      | Check DNS, the Gateway certificate and the cert-manager Certificate status. [Certificate renewal](./kubernetes#certificate-renewal) gives the one-host checks.                                  |

## Provider events

| Symptom                                                         | Check and recovery                                                                                                                                                               |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GitHub deliveries return `401`.                                 | Compare the configured webhook secret through a protected process. It must match the release Secret. Do not put either value in logs.                                            |
| Data appears only after a sync.                                 | Check that the provider webhook exists and reaches the webhook role. [Integrations](./integrations) links the provider-specific setup.                                           |
| Deliveries return `503` and `webhook.publish` records failures. | Inspect `webhook.publish.reason`, broker readiness, stream bounds and volume space. [Webhook ingestion operations](./webhook-ingestion-operations) owns recovery and redelivery. |

## Practice reviews

| Symptom                                                      | Check and recovery                                                                                                                                                                                            |
| --- | --- |
| Reviews record `No AI model is assigned to practice review.` | Assign an enabled model to practice reviews. [Connect an AI provider](./ai-providers) gives the steps.                                                                                                        |
| Sandboxes do not start or the worker is unready. | Inspect the worker isolation-probe result and sandbox Pod events. Verify the chart service account, namespace, quota, and NetworkPolicy. See [Kubernetes](./kubernetes#worker). |
| A sandbox Pod is refused or cannot start.                    | Inspect its events and the worker log. Check admission policy, quota, image pulls and [sandbox prerequisites](./kubernetes#sandbox-prerequisites).                                                            |
| A worker or sandbox ends with `OOMKilled`.                   | Compare its peak memory and limit under the qualified workload. [Sizing](./sizing) owns the resource budget.                                                                                                  |
| Reviews wait past their deadline.                            | Read queue depth and oldest age, then check the model and `worker.reviews`. [Sizing](./sizing) owns capacity. [Practice review operations](./practice-review-operations#queue-health) owns queue diagnostics. |
| Script runs end with `Practice script stopped without a result: it ran out of time.` | The model provider is slow or limits the rate of calls. [Practice review operations](./practice-review-operations) lists the reasons. Raise the provider limits or use a faster model before you raise concurrency. |

## Disk and storage

Check PostgreSQL data and WAL, JetStream, repository caches and the container runtime separately.
The kubelet owns image garbage collection.
Do not prune volumes to recover space.
A broker that could not write its metadata can need a restart after space is restored. Follow [Recovering a wedged broker](./webhook-ingestion-operations#recovering-a-wedged-broker).
Use [Backup and restore](./backup-restore) when data or a volume is lost.
