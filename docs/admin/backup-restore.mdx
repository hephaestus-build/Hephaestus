For the [self-host compose stack](./install). PostgreSQL holds application state. The Context Fabric
holds bounded evidence copies that may become irreproducible after upstream content changes or erasure.

## What to back up

| Data | Where | Priority |
| --- | --- | --- |
| PostgreSQL database | Compose-managed `postgresql-data` volume mounted by `postgres` | **Everything.** Accounts, workspaces, observations, feedback, encrypted provider tokens, JWT signing keys. |
| `release-lock.env` | `/opt/hephaestus/docker/self-host/release-lock.env` | The signed image digests matching the database backup. |
| `.env` | `/opt/hephaestus/docker/self-host/.env` | **Equal priority.** Its encryption keys protect values inside the database backup. Without them, provider credentials and signing material are unreadable. |
| TLS certificates | `./letsencrypt/` | Optional — Let's Encrypt re-issues on first boot (rate limits permitting). |
| Context Fabric | `git-repos` volume | Back up when replayable evidence is required. Skipping it discards repository clones and bounded replay/CAS content; durable job provenance remains in PostgreSQL, but the exact source bytes may be unrecoverable. |
| NATS JetStream | `nats-data` volume | Pending events; preserve for reconciliation with the restored database. |

## Backup

PostgreSQL MVCC gives a consistent database snapshot while the application runs. Do not deploy or
rotate encryption keys until the database, configuration and release lock have all been captured:

```bash
(
set -euC
umask 077
cd /opt/hephaestus/docker/self-host
dc() { docker compose --env-file .env --env-file release-lock.env "$@"; }
backup="hephaestus-$(date -u +%Y%m%dT%H%M%SZ)"
dc exec -T postgres pg_dump -U root -Fc hephaestus > "$backup.dump"
cat .env > "$backup.env"
cat release-lock.env > "$backup.release-lock.env"
)
```

Ship all three files **off the host**, encrypted. Cron it daily; test-restore it at least once (below).

## Restore

On a fresh host, complete install steps 1–2 first, restoring the saved `release-lock.env` and `.env` (same
`POSTGRES_PASSWORD` and both `HEPHAESTUS_SECURITY_*ENCRYPTION_KEY` values). Replace
`hephaestus-TIMESTAMP.dump` below with the timestamped dump from that backup:

```bash
(
set -eu
cd /opt/hephaestus/docker/self-host
dc() { docker compose --env-file .env --env-file release-lock.env "$@"; }
dc up -d --wait postgres
dc stop application-server webhook-server

test -s hephaestus-TIMESTAMP.dump
dc exec -T postgres pg_restore --list < hephaestus-TIMESTAMP.dump >/dev/null
dc exec -T postgres dropdb -U root --if-exists hephaestus
dc exec -T postgres createdb -U root hephaestus
dc exec -T postgres pg_restore -U root -d hephaestus --no-owner --no-acl --single-transaction \
  < hephaestus-TIMESTAMP.dump

dc up -d --wait
)
```

Verify: sign in, open a workspace, check recent activity is present up to the backup
timestamp.

## Unsupported PostgreSQL versions

Only PostgreSQL 18 is supported. For an existing PostgreSQL 17 installation, follow the
[PostgreSQL 17 to 18 migration procedure from v0.77.4](https://github.com/hephaestus-build/Hephaestus/blob/v0.77.4/docs/admin/backup-restore.mdx#postgresql-17-to-18).
Do not attach an older data directory to PostgreSQL 18 or change the image tag as an upgrade.
Keep an encrypted, off-host backup and successfully rehearse its restore before removing any data
volume; `pg_restore --list` checks the archive contents, not recoverability.

## After a point-in-time restore

- **Sessions and credentials:** users signed in after the backup was taken must sign in again.
  If restored signing keys cannot be read, verify the matching encryption configuration rather than
  deleting the keys. Review access revocations and credential rotations made after the recovery point
  before reopening access.
- **NATS JetStream:** preserve the queue while reconciling it with the restored database. Its
  events may already have been processed or may fall after the backup's recovery point. Do not
  delete `nats-data` as a routine recovery step. Provider sync may recover current state, but cannot
  guarantee recovery of every event or content that has since changed or been deleted.
- **Restore into an older app version:** don't. Restore with the same signed release lock the backup was taken from, then upgrade.
