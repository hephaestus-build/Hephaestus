| Key | Type | Default | Required in object | Constraints |

| `server.databasePool.maximumPoolSize` | integer or string | `"auto"` | yes | `oneOf: [{"type":"integer","minimum":1,"maximum":400},{"const":"auto"}]` |

| `server.drainTimeoutSeconds` | integer | `1800` | yes | Whole seconds. The chart emits a Spring Boot Duration for the server's drain and an integer Kubernetes termination grace period.<br />`minimum: 0. maximum: 86400` |
| `server.gitCache.sizeLimit` | string | `"70Gi"` | yes | This role's Git cache volume, in whole Mi or Gi. Kubernetes reads this quantity as written. The chart keeps one snapshotLimit of it for each review and each conversation load that the server runs at once, and gives the application the rest as its eviction budget. Everything on the volume counts against that budget: above 80 % of it, the server deletes the Git mirrors that it used least recently. The chart refuses a volume that leaves less than 1Gi for the mirrors.<br />`pattern: "^[1-9][0-9]*(?:Mi\|Gi)$"` |
| `server.gitCache.snapshotLimit` | string | `"2Gi"` | yes | The most disk that one snapshot may use, in whole Mi or Gi: a checkout with its history for a review, a conversation's context load, or a scan.
