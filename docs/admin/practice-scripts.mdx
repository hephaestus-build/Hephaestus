A practice script returns one result for one practice and one piece of work.
It can decide from the captured records, or prepare evidence and let the review model decide.
Every result passes the same checks on the server.
This page lists the API that a script can use.
An admin enters a script in the **Script** field of the practice editor, as [Practices](/user/practices#practice-script) describes.

## Script shape

A script has a default export from `definePracticeScript`, with an empty `meta` and a `run(ctx)` function.
This script does what the built-in script does:

```ts
import { definePracticeScript } from "@hephaestus/practice-scripts";

export default definePracticeScript({
  meta: {},
  async run(ctx) {
    return ctx.review();
  },
});
```

An empty **Script** field runs the built-in script.
An invalid custom script stops with a recorded reason. It never falls back to the built-in script.
A stored script with any field in `meta` is invalid.

## The context

The host supplies the practice version, its criteria, the assigned scope, the origin, and About.
The core record of the work is unknown until a domain kit validates it.
Big integer IDs are decimal strings, not JavaScript numbers.
A script cannot choose another workspace, developer, or recipient.

`ctx.review` opens the model review. Pass it leads, facts, directions, prepared context, or limitations.
The script ends at `ctx.review`: code after it does not run.
Only the value that `run` returns reaches the server.

For a review of a piece of work, the scope names that work and its version.
For a scan, the scope names one file at the scanned commit of the default branch, and About is null.
The previous result is metadata for the same claim. It is not proof for a new result.

## Domain kits

A domain kit validates the record of the work before it gives source-specific helpers.
The kit states the kinds of work that the script reads. Another kind stops the script.
Do not cast the unknown core record into a provider payload.

This SCM example keeps the normal review and adds a typed fact:

```ts
import { definePracticeScript } from "@hephaestus/practice-scripts";
import { scm } from "@hephaestus/practice-scripts/scm";

export default definePracticeScript({
  meta: {},
  async run(ctx) {
    const work = scm(ctx, "scm.pull_request");
    return ctx.review({ facts: { changedFiles: work.item.changed_files } });
  },
});
```

`work.sites` finds places in changed code, with rules for each language:

```ts
const found = await work.sites({
  swift: [{ kind: "forced-try", label: "A changed try! expression.", test: /\btry!/u }],
});
const directions = found.leads.length > 0 ? ["Read whether each one can fail."] : [...found.noMatch];
return ctx.review({ leads: [...found.leads], directions });
```

A site is on an added line of the change, or anywhere in the file of a scan.
Comments and strings do not match, unless you set `comments: true`.
Which lines match is not part of the [compatibility policy](./compatibility-policy).
Each lead is a place for the review to read, never a verdict.

## The script API

These names are the whole API. They hold for a major version of Hephaestus, as the [compatibility policy](./compatibility-policy) states.
A script can import nothing else, also no Node module and no package.

| Import | Names |
| --- | --- |
| `@hephaestus/practice-scripts` | `definePracticeScript`, `UnratedError`, `listWithin` |
| `@hephaestus/practice-scripts/scm` | `scm`, `isTestPath`, `languageOf`, `checkableItems`, `issueReferences`, `branchIssueReferences`, `issueShape`, `subIssueRollup`, `later`, `dated` |
| `@hephaestus/practice-scripts/chat` | `chat` |
| `@hephaestus/practice-scripts/docs` | `docs` |

The `work` object from `scm` has `kind`, `item`, `head`, `change`, `changedFiles`, `sources`, `sites`, `commits`, `linkedIssues`, `inlineComments`, `conversationComments`, `reviewRecord`, and `checks`.
A read that returns null means that the source was not captured. It never means empty.
A malformed record stops the script.

## Results

A result is **Met**, **Not met**, **Does not apply**, or **Could not determine**.
The [outcome contract](/contributor/practice-feedback-language#observation-outcomes) gives their meanings and requirements.

- Each problem has its own severity, citations, and claim basis. A result has no severity of its own.
- **Not met** can keep open questions beside the problems that it establishes.
- A failed read or a failed model call never becomes an open question.
- Return the result of `ctx.review`, or a result that your code decided, without `coverage`. Hephaestus measures coverage from the reads of the script.
- A **Met** in a scan needs a complete read of the assigned file. A listing, a search match, or a count alone does not prove that read.
- Citations quote captured text that the reader may see. The host verifies the location, the version, and the basis before the result can support feedback.
- A partial read or a cut search can support **Not met**, but not **Met** or **Does not apply**.

A result that your code decided must rest on evidence that your code read.
The host refuses it with **Decided without its evidence** if a read failed, a record was missing, or a kit could not trust a record.
This applies even if your code caught the error.
You can still call `ctx.review` after such a failure. The coverage of its result then names what the script could not read.

## Review model

The script context has no model slots and no model helpers.
`ctx.review` uses the review model that the workspace assigns.
The review follows the developer's AI choice.
The workspace sets the model and its budget, as [AI models and spending](/user/ai-models) describes.

## Limits

| Limit | Value |
| --- | --- |
| Directions | 10 at most. More is an error of the script. |
| Leads | 200 at most. More is an error of the script. |
| A direction or a fact that is too long | Folded to one line and cut |
| An empty fact | Dropped |
| Time | The deadline of the review attempt. No separate time is reserved before the review. |

The host makes the provider calls and holds their budget reservations.
A failed or unreported call keeps its reservation.
The [runner contract](/contributor/practice-script-runner#review-limits) gives the size limits of the result and its citations.

## Stop reasons

| What the review shows | Cause |
| --- | --- |
| “The script's default export is not a practice script. Write it with definePracticeScript.” | The default export has the wrong shape. |
| **Not a runnable script** | The script imports a name outside [the script API](#the-script-api). The message names the import. |
| **Decided without its evidence** | The script decided a result after a read that failed, as [Results](#results) describes. |

To see what a script did, open the review in **Practice reviews**, then open **Practice scripts**.
[The trace line](./practice-review-operations#the-trace-line) explains what it shows.

[Practice script runner](/contributor/practice-script-runner#test-a-script-locally) describes how to test a script in a checkout of Hephaestus.
