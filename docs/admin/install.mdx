Hephaestus runs from its signed Helm chart on Kubernetes.
For one Linux host, use the [k3s installation](./kubernetes#install-on-one-host-k3s).
For an existing cluster, follow [Install](./kubernetes#install).
Both procedures install the same chart.

## Requirements

### Supported host matrix

Check the [platform requirements](./kubernetes#requirements) before you prepare a one-host installation.
For an existing cluster, check [cluster requirements](./kubernetes#supported-clusters).
The [sizing guide](./sizing) gives the workload budget.

### Tested versions

The [Kubernetes guide](./kubernetes) owns the supported Kubernetes, Helm and platform versions.
Use the images and chart digest from the release that you install.
[Release image lock](./release-image-lock) explains their verification.

### Clocks

Keep the clock of every host that runs a Hephaestus role or PostgreSQL synchronized by NTP.
Conversation turn leases and person erasure compare times that different hosts write.
If Slack does not answer when Hephaestus starts a streamed reply, the server looks for that reply in the thread by time.
Hephaestus assumes that Slack's clock and the server's clock differ by less than 2 seconds.
[Conversation runtime § Slack replies](/contributor/unified-pi-runtime#slack-replies) has the rule.

## Install

1. Read the release notes and [migration guide](https://github.com/hephaestus-build/Hephaestus/blob/main/MIGRATION.md).
2. [Verify the release chart](./kubernetes#verify-the-release-chart).
3. Install it with your site values and the referenced Secret.
   [Secret custody](./secret-custody) lists the keys to keep outside the cluster.
4. Complete [First steps](./first-steps): configure sign-in, identify the first admin, and connect a workspace.
5. Configure [integrations](./production-setup), [AI providers](./ai-providers), and the [practice catalog](./practice-catalog).
6. Configure and rehearse [backup and restore](./backup-restore) before you admit work.

## Upgrades

Follow [Upgrade](./upgrade) and the release's migration guide.
The [channel reconciler](./pull-based-deployment) applies a signed release chart or the image pins of a verified commit channel.
An irreversible schema upgrade uses the [stopped upgrade procedure](./kubernetes#stopped-schema-upgrades).
