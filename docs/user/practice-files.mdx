A practice can be written as a folder of files.
The files hold the same definition that the practice editor saves.
A folder is a second way to write a practice, not a second kind of practice.

## Download a practice as files

1. Open **Practices**.
2. Open **More actions** on the practice's row, and select **Download as files**.

You get a ZIP archive with one folder, named after the practice's slug.
An MCP client gets the same files with the tool `export_practice` ([Connect MCP clients](/admin/mcp-clients)).

## Check a practice folder

The MCP tool `check_practice_files` checks a folder without saving it, and calls no model.
It returns each problem with its file, line and column.
The check applies the same rules as a save in the practice editor.

## Try a practice folder

An MCP client with permission to change practices can try a folder on one pull request, merge request or issue:

1. `save_practice_draft` saves the folder.
   A new slug becomes a draft practice, which reviews nothing until you activate it.
   For a practice in use, the folder becomes a version beside the current one, and reviews keep using the current version.
2. `try_practice` runs the saved version on the work and waits up to 50 seconds.
   A trial records no observation and sends no feedback. It counts against the workspace's AI budget.
3. `get_practice_trial` reads a trial that is still running.

A trial always gives its status and outcome.
It gives each problem and the cited lines only if every person whose work it read chose **Cloud**.
`remove_practice_draft` deletes a draft practice and its trials.

## Keep practices in a repository

A workspace can keep its practices as folders in one monitored repository, its **practice repository**.
The folders live on the default branch, under `.hephaestus/practices/` unless you name another directory.

1. Open **Practice setup**. In **Practice repository**, choose **Set practice repository**.
   Choose a repository that the workspace monitors.
   Optionally, name the directory of the practice folders, as a path from the repository root.
2. Commit the folder of a practice on the default branch. **Download as files** gives it.
3. Open the practice in **Practice setup**, choose **Move to repository**, and confirm.
   Hephaestus reads the folder at the head of the default branch.
   When it refuses the move, it shows the reason.
   For a folder that is not valid, it also lists each problem with its file and, where known, its line and column.
   When the folder's definition differs from the current version, it becomes the next version.

**Change** and **Unset** in **Practice repository** first ask you to confirm.
Changing the repository or the directory makes every practice edited in the old one editable in Hephaestus again.
Automation can do the same through the API, under `/api/workspaces/<slug>/practice-repository`.

A practice edited in the repository is read-only in Hephaestus, except for its feedback mode and position.
In **Practice setup**, it shows **Edited in the practice repository**.
Its panel names the repository and, when its current version was read from there, the commit.
You cannot edit it, delete it, move it to another group, or reset it to the catalog.
You also cannot accept a catalog update for it, or delete the group that it is in: its folder names that group.
In **Practice reviews**, the history of the practice shows the commit of each version from the repository.

To change the practice in Hephaestus again, open it in **Practice setup** and choose **Edit in Hephaestus**.
The practice keeps its current version.
Later changes to its folder no longer reach the practice.
Changing or unsetting the practice repository makes every practice edited there editable in Hephaestus again. Nothing is deleted.

Anyone who can merge into the default branch of the practice repository changes what reviews judge, and the practice scripts that run in review sandboxes.
Protect that branch as you protect your code: require a review before a merge.
Setting or unsetting the practice repository, and moving a practice to it or back, each need a recent sign-in.

## The folder

The folder name is the practice's slug: lowercase letters and digits, with single hyphens.

| File | Holds | Required |
| --- | --- | --- |
| `practice.md` | The front matter, then the criteria as the Markdown body | Yes |
| `guide.md` | The text of the **Guide** tab | No |
| `figures/<name>.svg` | A figure of the guide. `guide.md` shows it by its path, `figures/<name>.svg`. [Practice visual rules](./practice-visual-rules.mdx) has the syntax. | No |
| `visual.svg` | The practice visual | No |
| `script.ts` | The practice script | No |

A folder holds no other files.
Each file is at most 128 KiB, and the folder is at most 256 KiB.
[Practice visual rules](./practice-visual-rules.mdx) lists what a visual, a guide and a figure can contain.

## The front matter

`practice.md` starts with a line `---`, then the YAML front matter, then another line `---`.
Everything after the second `---` is the criteria.

```markdown
---
format: hephaestus.practice/1
name: Changesets speak to the reader
kind: scm.pull_request
reviewOn:
  events: [scm.pull_request.opened, scm.pull_request.ready]
about: AUTHOR
reads:
  contract: 3.0.0
  sources:
    - { source: scm.pull-request.core, need: REQUIRED }
    - { source: scm.pull-request.diff, need: REQUIRED }
reviewedBy:
  by: HEPHAESTUS
---
REVIEW FOCUS: each changeset is a release note for an operator or a user.
```

| Key | Practice editor field | When you leave it out |
| --- | --- | --- |
| `format` | none | Required. Use `hephaestus.practice/1`. |
| `name` | Name | Required |
| `kind` | The kind of work that the practice reviews | Required |
| `group` | Group, by its slug | The practice has no group. |
| `reviewOn` | **Review on** (`events`) and **When** (`state`) | Required. Without `state`, every state matches. |
| `about` | **About** | Required. `null` means **The work**. |
| `appliesWhen` | **Applies when** | The practice applies to all work of its kind. |
| `reads` | **Reads** | Required |
| `reviewedBy` | **Reviewed by** (`by`, `humanReason`, `limits`) | Required. Without `limits`, there are none. |
| `lineNotes` | Line notes | `false` |
| `scan` | Scan settings | The practice has no scan. |
| `guidance` | **Why it matters** (`whyItMatters`), **What good looks like** (`whatGoodLooksLike`), **Going well** (`goingWell`), and the description of the visual (`visualAlt`) | No guidance text. `visualAlt` is required with `visual.svg`. |

Hephaestus refuses a key that is not in this table, and a `format` that it does not know.
