The Hephaestus Chrome extension puts a **practice review** in the pull request, merge request, or issue page open in your tab.
It appears after the description.
It shows comments Hephaestus posted there for you, links to them, the review time, and conclusions about your work.

**Open in Hephaestus** opens the same records in the app, on the page called **Your feedback on this work**.
That page also shows each earlier review of the work.
Workspace admins can also reach everyone’s records in **Practice reviews**.

The extension adds context.
It is not another channel for feedback.
Feedback still appears on the work, on your [Practice profile](./practice-profile), and in Heph.
[Practice feedback](./ai-code-review#where-feedback-appears) describes those channels.

## Before you start

You need:

- **Chrome on a desktop computer.** Chrome on Android and iOS cannot run desktop extensions.
- **A Hephaestus account** on an instance that allows the extension.
- **Membership in a workspace** that monitors the repository you view.

1. If sign-in says **This instance does not know this extension**, ask its operators to allow it.

The extension is not yet in the Chrome Web Store.
Instance operators either install it through your organization’s Chrome settings or supply a package with installation instructions.
The package method requires Chrome developer mode.

## Connect it to your Hephaestus

1. If you cannot see the Hephaestus icon, pin it from Chrome’s puzzle-piece menu.
2. Select the Hephaestus toolbar icon to open extension settings.
3. For the hosted service at `hephaestus.build`, select **Connect to Hephaestus**.
4. For the hosted service, allow Chrome’s request for extension access to that address.
5. For your organization’s own Hephaestus instead, open **Use a self-hosted instance**.
6. For a self-hosted instance, enter its HTTPS address.
7. Select the sign-in button for your usual provider, such as **Sign in with GitHub**.

If settings say **One step left in Hephaestus**:

1. Select **Open Hephaestus**.
2. Finish the step shown, for example by accepting the current notice.
3. Return to extension settings.
4. Select **Check again**.

You can change the instance later on the same page.
The sign-in window opens on your Hephaestus and sends you on to GitHub or GitLab, as the web app does.
It uses your normal Chrome profile, so you may not need to sign in to the provider again.
After sign-in, the window closes and settings show who you’re signed in as.
If you close the window before you finish, nothing changes and you can try again.

### Allow it on GitHub and GitLab

The extension reads nothing on a site until you allow it.
Settings list sites connected to your workspaces: `github.com`, `gitlab.com`, or your organization’s GitLab address.
Each site needs its own permission, and Chrome asks each time.

1. In extension settings, select **Allow** beside each site you need.
2. To stop the extension on a site, select **Remove** beside it, or remove it in Chrome’s extension settings.

Once you allow a site, each pull request, merge request, or issue you open there makes the extension look it up on Hephaestus right away.
[Privacy](#privacy) explains these requests.
If no site appears, you do not yet belong to a workspace that is connected to GitHub or GitLab.

1. If no site appears, select **Open Hephaestus** to see your workspaces, or ask to join one.

## The practice review on the page

On supported pages, the review uses the page’s content column:

- On a GitHub pull request, after its description and before the conversation.
- On a GitHub issue, after its description and before the activity.
- On a GitLab merge request, with its reports and before the activity.
- On a GitLab issue or work item, at the top of its activity.
- On pull request or merge request changes, above the changed files.

The review starts as one line, and the line has the same height in every state.
It shows, in order:

1. A pending or deferred decision recorded for your review, such as *Review decision pending*.
2. The number of comments Hephaestus recorded as posted for you on this work.
3. The latest review time.
4. How many practices the review could not finish, such as *1 practice incomplete*.

For example: *3 comments for you · reviewed 2 hr. ago*.

1. Select the line to expand the report in place.
2. Select it again to close the report.

The page moves down to make room, without an overlay.
The extension remembers that the report is open while you stay on the same work in that tab.
This includes when you switch to the changes and back.
While the report loads, the line reads *Loading…*.
If the report cannot start at all, it says *We could not load here*.

1. If the report cannot start, reload the page.

The report belongs to the extension, so the page cannot read its content.
It follows the page’s light and dark modes, including GitHub’s dimmed and high-contrast themes.

### What the report shows

The expanded report is one flat list, with no further expansion controls:

- **Your comments.** Each row is a comment Hephaestus posted for you on this work. The summary comment, or the file and lines, link to the comment on the page. You read, answer, and resolve it there. The report never repeats the text. Below the link, it shows the practices and the delivery time.
- **Your observations** show what the review concluded about your work, one row per observation. Each row names the practice, the outcome, the severity for **Not met**, and a one-sentence summary. The outcomes are **Met**, **Not met**, **Not applicable**, and **Undetermined**. An observation from before a change to the practice or the work says it is no longer current. The first five appear, and **Show … more** reveals the rest.
- **When, and where to read more.** The report shows the exact time of the latest review, and its commit if known. **Open in Hephaestus** opens your feedback and observations on the work.

On the changes page, comments on lines appear first.
The comment list shows what Hephaestus recorded when it posted.
Someone may have changed or deleted a comment since then.
A comment with no recorded address says *no link recorded*.
A comment posted while the rest of its feedback could not be posted names no practice.

Workspace admins also get **Review details**, including instance admins who work in the workspace.
It shows each developer’s observations, each piece of feedback’s delivery state, and each review run.
A run there can be canceled or its results retried.

**No recorded comments does not mean no problems.**
*No recorded comments for you* only means that Hephaestus recorded no comment for you on this work.
It is not a clean result.
The work may be unreviewed, or no practice may check the event that occurred.
*Review status unavailable* means your account has no available review trace.
It does not prove the work was never reviewed.

## Previewing work from a list

On GitHub repository lists of pull requests or issues, each row has a small Hephaestus button after its title.
GitLab project lists of merge requests, issues, or work items get the same button.
Nothing is looked up until you select one.

1. Select a row’s Hephaestus button.
2. To open the full report, select the row’s title.
3. To request a review, open the work.

The preview shows one quiet line below the row title.
It uses the first sentence of the work’s report and links to your first comments there.
Nothing else expands in the row, and no changes happen from the list.
Only one preview is open at a time.
Another row’s button moves the preview.
The same button, or a list filter or page change, closes it.

## Acting on what you see

You read in the report.
The only change you can make from the page is a review request.
You always confirm it in a separate small Hephaestus window, which the page cannot cover or read.

**Request review** appears on the work page when you may request a review, as author, assignee, or workspace admin.
It appears only when no review of that work is queued or running.

1. Select **Request review** on the work page.
2. Check the work and workspace named in the confirmation window.
3. Select **Request review** in that window.

The extension sends nothing before confirmation.
If Hephaestus does not start a review, the window shows the reason Hephaestus gave.
If no answer arrives, the window says the request may or may not have gone through.
It does not retry.

1. If no answer arrives, check the page report first.

You cancel a review, retry its results, and approve or reject feedback in Hephaestus, through **Review details**.

## How long you stay signed in

You stay signed in until you close Chrome or seven days pass, whichever comes first.
Your instance may set a shorter limit.

1. After sign-in ends, sign in again from settings.

Under **User settings**, the session appears as *Browser extension in Chrome on …*.
Ending that session there, signing out everywhere, or an instance admin ending your sessions also signs the extension out.

1. To sign out, select **Sign out** in extension settings.

Signing out, or changing the Hephaestus address, clears the extension’s content from every tab.

## Privacy

- On an allowed site, the extension immediately sends opened work addresses to Hephaestus for lookup. This includes pull requests, merge requests, and issues. It sends the address again while the page stays open and the review may change. On lists, it sends a row’s address only after you select its Hephaestus button. It sends no other addresses, including from other sites.
- It does not read or send page content or read cookies. Requests to Hephaestus use its own sign-in, not browser cookies.
- Report content stays inside the extension’s page area. The page sees only the report’s presence and height.
- Sign-in stays in Chrome memory for the extension only. When Chrome closes, it removes the sign-in.
- Hephaestus matches the address against repositories the workspace already monitors. It does not fetch the page itself.

[Your data in Hephaestus](./privacy) and [the extension’s data handling](./browser-extension-privacy) explain recorded data and access.

## When something is not right

| The report starts with              | What it means                                                                                                     |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| We could not load here              | The report did not start.                                                                                         |
| We could not load                   | Your Hephaestus did not answer.                                                                                   |
| We could not load your comments     | The report loaded, but your comments did not.                                                                     |
| Connect the extension to Hephaestus | The extension is not connected yet.                                                                               |
| Sign in to … to see it              | Your sign-in ended.                                                                                               |
| One step left in Hephaestus         | Your account needs a web-app step, such as acceptance of the current notice.                                      |
| Not available for this work         | No workspace connects to this site, or the work is not in an accessible workspace.                                |
| Followed in 2 workspaces            | Multiple workspaces follow this work. The extension never chooses for you.                                        |
| No recorded comments for you        | Hephaestus recorded no comment for you here. [What the report shows](#what-the-report-shows) explains the limits. |
| Not refreshed                       | Hephaestus did not answer the latest refresh. The report shows its last answer and that answer’s time.            |

For **We could not load here**:

1. Reload the page.
2. If the problem continues, open settings from the toolbar icon.
3. Check that you are signed in.

For **We could not load**:

1. Check your connection.
2. Select **Retry**.

For **We could not load your comments**:

1. Open the report.
2. Select **Retry**.

For **Connect the extension to Hephaestus**:

1. Select **Set up**.

For **Sign in to … to see it**:

1. Select **Sign in**.

For **One step left in Hephaestus**:

1. Open Hephaestus.
2. Complete the required step.
3. Return to the extension.

For **Not available for this work**:

1. Open the report. It gives the reason if it can tell.

For **Followed in 2 workspaces**:

1. Open the report.
2. Choose a workspace.

For **Not refreshed** in a list preview:

1. Select **Retry**.
