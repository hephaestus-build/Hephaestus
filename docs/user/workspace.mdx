A workspace contains the repositories, members, teams, practice catalog, integrations, and feature settings for one group. A Hephaestus deployment can host more than one workspace, and a person can belong to several.

Use the workspace switcher at the top of the sidebar to move between the workspaces you can access.

Hephaestus keeps you on the same kind of page when it applies to both workspaces. From a page for a specific person, conversation, practice, or other workspace item, switching opens the workspace home page instead. A page option that names something in the workspace you are leaving, such as a team filter, is cleared. Most other page options reset too; the leaderboard keeps its sorting, time range and view. If you open a link to a workspace that is no longer available to you, Hephaestus opens the home page of another workspace you can access, or tells you that you are not in a workspace yet. Signing in opens the first workspace you can access.

## Create a workspace

Who can create workspaces depends on the deployment. The default policy limits creation to instance admins.

When creation is available:

- **GitHub:** install the Hephaestus GitHub App on an organisation. Hephaestus creates the workspace from the installation.
- **GitLab:** connect a supported GitLab instance with an access token, choose a group, and finish the creation wizard.

If **Create workspace** is not available to you, ask an instance admin.

## Repositories

How repository access is managed depends on the connection:

- For a **GitHub App** workspace, change repository access in the app installation on GitHub. Hephaestus mirrors the repositories granted to the app.
- For a **token-managed** workspace, a workspace admin can open **Administration → Integrations**, enter a repository as `owner/name`, and select **Add**. Removing a monitored repository permanently deletes the data Hephaestus mirrored from it; the upstream repository is not changed.

Initial sync time depends on the size and history of the connected repositories. Later changes are picked up by webhooks and scheduled reconciliation.

## Members and teams

Members and teams are scoped to one workspace.

- GitHub App workspaces mirror organisation members, teams, and repository access from GitHub.
- GitLab workspaces mirror the connected group and its projects.
- Workspace admins can review membership and role information under **Administration**.

If source-managed membership is wrong, correct it in GitHub or GitLab and wait for the next sync.

## Directory-managed access

If your organization uses directory-managed access, open **User settings → Workspace access**.
Connect your organization's sign-in method under **Connected Accounts** using your existing account.
A matching name or email does not connect accounts. Eligible workspaces appear only after a complete,
current directory read. Choose **Join workspace** on an offer; this grants a Member role, never
ownership. A suspension requires an explicit owner decision and cannot be bypassed by linking again.

Workspace owners configure **Administration → Directory access** using a source and group IDs already
approved by an instance administrator. Save the dedicated read-only directory credentials, preview the
saved configuration, inspect the proposed changes, and approve that preview. Workspace administrators
can inspect the policy and reconcile it, but only owners can change eligibility or approve it.

Directory management removes only the access it manages after a complete read confirms departure.
Manual access and ownership are preserved. Owners can explicitly **Adopt** an eligible non-owner's
access into directory management; this changes their role to Member, even if they were an
administrator, and preserves any suspension.

**Pause new access** stops additions while confirmed departures still remove managed access.
**Resume new access** requires a fresh read. **End management** removes managed access immediately
without changing manual access, ownership or suspensions. An outage or stale read blocks new grants
but is never treated as proof that everyone left. Disconnecting the organizational identity also
removes its managed access.

## Practices and AI

Workspace admins choose:

- which engineering practices are active
- whether practice reviews run automatically or can be triggered manually
- whether Heph is available
- which connected AI model powers practice reviews and Heph
- the monthly AI spending cap

These settings apply only to that workspace.

## Optional features

Workspace admins can separately enable the leaderboard, progression, leagues, and Slack. A feature that is off does not appear in the member navigation.

## Troubleshooting

- **Workspace missing?** Confirm that you are signed in with an identity linked to a workspace member.
- **Repository missing?** Check the GitHub App installation or the monitored repository list, depending on the connection type.
- **Team missing?** Confirm that the team exists in the connected source platform and has synced.
- **Feature missing?** Ask a workspace admin whether it is enabled and whether your account has access.

## Requesting access

If your workspace accepts applications, open its **Request access** page. Your workspace administrator
can share the link. Sign in with the provider shown there; it matches the workspace's GitHub or GitLab
organization. If you are already signed in with a different provider, connect the requested provider
to your existing account rather than creating another account.

Select **Continue** to check existing organization membership. If you already have access, Hephaestus
opens the workspace. Otherwise:

1. Connect any additional accounts required by the workspace. You return to the access page after each
   connection. A verified email address is required for notifications.
2. Read the introduction and code of conduct, then acknowledge them.
3. Choose your responsible maintainer, the teams you need and the date your access should end.
4. Read and acknowledge the workspace notices. These do not change your optional research consent.
5. Submit your request. Its status and the administrator's explanation appear under **Your requests**.

An administrator may approve access, adjust the approved details, ask you to submit changes, or decline
the request. You can withdraw an undecided request. An approval gives you Hephaestus access until the
approved deadline; an external organization invitation may still need to be delivered and accepted.

### Renewing access

An expiry reminder links back to the renewal page. Submit the new end date and review the current
workspace notices. **A pending renewal does not extend your existing access.** Access ends at its
approved deadline unless an administrator approves a renewal first. You can still read your requests
and apply for renewed access after expiry.
