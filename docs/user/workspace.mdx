A workspace contains the repositories, members, teams, practice catalog, integrations, and settings for one group. A Hephaestus deployment can host more than one workspace, and a person can belong to several.

Use the workspace switcher at the top of the sidebar to move between the workspaces you can access.

Hephaestus keeps you on the same kind of page when it applies to both workspaces. From a page for a specific person, conversation, practice, or other workspace item, switching opens the workspace home page instead: your Practice profile, or Activity where the workspace does not review practices. A page option that names something in the workspace you are leaving, such as a team filter, is cleared. Most other page options reset too; the Activity pages keep their time range. If you open a link to a workspace that is no longer available to you, Hephaestus opens the home page of another workspace you can access, or tells you that you are not in a workspace yet. Signing in opens the first workspace you can access.

## Create a workspace

Who can create workspaces depends on the deployment. The default policy limits creation to instance admins.

When creation is available:

- **GitHub:** install the Hephaestus GitHub App on an organisation. Hephaestus creates the workspace from the installation.
- **GitLab:** link your GitLab account on the GitLab instance your deployment uses, enter an access token for it, choose a group, and finish the creation wizard. The workspace belongs to that GitLab account.

If **Create workspace** is not available to you, ask an instance admin.

## Repositories

How repository access is managed depends on the connection:

- For a **GitHub App** workspace, change repository access in the app installation on GitHub. Hephaestus mirrors the repositories granted to the app.
- For a **token-managed** workspace, a workspace admin can open **Administration → Integrations → GitHub/GitLab → Manage repositories → Add a repository** and enter its full repository path. Removing a monitored repository permanently deletes the data Hephaestus mirrored from it; the upstream repository is not changed.

Initial sync time depends on the size and history of the connected repositories. Later changes are picked up by webhooks and scheduled reconciliation.

## Members and teams

Members and teams are scoped to one workspace.

- GitHub App workspaces mirror organisation members, teams, and repository access from GitHub.
- GitLab workspaces mirror the connected group and its projects.
- Workspace admins can review membership and role information under **Administration**.

If source-managed membership is wrong, correct it in GitHub or GitLab and wait for the next sync.

## Practices and AI

Workspace admins choose:

- which engineering practices are active
- each practice's feedback setting: **Off**, **Review before sending** (the default), or **Send automatically**. Review before sending records observations but waits for a workspace admin to approve feedback on the work
- whether practice reviews run automatically or can be triggered manually
- which connected AI model powers practice reviews and Heph; Heph is offered to every member once a
  model for it is set up
- the monthly AI spending cap

These settings apply only to that workspace.

[Activity](./activity) is part of every workspace and has no setting of its own; see there for hiding
a member or a team from workspace activity.

## Troubleshooting

- **Workspace missing?** Confirm that you are signed in with an identity linked to a workspace member.
- **Repository missing?** Check the GitHub App installation or the monitored repository list, depending on the connection type.
- **Repository or Slack channel sync error?** Open **Administration → Integrations → GitHub/GitLab → Manage repositories** for a repository, or **Administration → Integrations → Slack** for a channel, and check the affected resource's last error. Check its access in the connected service, then run a new sync. Each error clears after its affected sync path succeeds; a skipped pass keeps its error.
- **Team missing?** Confirm that the team exists in the connected source platform and has synced.
- **Practice profile missing?** Ask a workspace admin whether practice reviews are on in this workspace.
- **Heph not answering?** See [Who can use Heph](./ai-mentor#who-can-use-heph).

## Your AI choice

Your choice applies across all your workspaces. See [User settings](./user-settings#your-ai-choice)
for **In-house**, **Cloud**, **No AI**, and the account links required during first-visit setup.

## GitLab token alerts

Hephaestus checks GitLab tokens each day and rotates a token before it expires when GitLab permits it.
The connection page shows its expiry date, or **no expiry**. If a token cannot be rotated or GitLab
refuses it, replace it in workspace integration settings. Your repositories and synced work stay.

Owners and administrators can enable the **Workspace alerts** email in notification settings.
It reports a token that needs replacement and reports recovery after rotation or replacement.
Repeated checks of the same problem do not send duplicate alerts. GitHub App tokens renew
automatically; GitHub personal access token expiry is not tracked.

## Unavailable repositories

If a monitored GitHub or GitLab repository cannot be read, **Administration → Integrations** shows
**Repository not found or not accessible**. This does not mean that the repository was deleted.
It can also mean that its name changed or that the connection no longer has access.
Hephaestus keeps the monitor and the work it has already stored.

After two consecutive unavailable responses, Hephaestus checks the repository at most once every
24 hours. Recent sync and backfill wait while it is unavailable. A successful check clears the error
and resumes sync automatically. Connection authentication errors, rate limits, and network errors
keep their normal retry behavior.

To recover, give the connection access to the repository again. A workspace admin can select
**Sync now** on the connection to check immediately instead of waiting for the next daily check.
If you no longer want the repository in the workspace, stop monitoring it. For a GitHub App
connection, change repository access in the installation. For a token-managed connection, remove
it from the monitored repositories. Removing a monitor permanently deletes its mirrored data;
it does not delete the upstream repository.
