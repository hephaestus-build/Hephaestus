A workspace contains repositories, members, teams, a practice catalog, integrations, and settings for one group.
A Hephaestus deployment can host multiple workspaces.
A person can belong to several.

1. Use the workspace switcher at the top of the sidebar to select an accessible workspace.

Hephaestus keeps the same kind of page if it applies to both workspaces.
From a page for a specific person, conversation, practice, or other workspace item, a switch opens the workspace home instead.
This is your Practice profile, or Activity if the workspace does not review practices.
Options that name resources in the previous workspace, such as team filters, clear.
Most other options reset too, but Activity pages keep their time range.

If a linked workspace is no longer accessible, Hephaestus opens another accessible workspace's home page.
If none is accessible, it states that you are not in a workspace yet.
Sign-in opens the first accessible workspace.

## Create a workspace

Creation permissions depend on the deployment.
The default policy permits only instance admins to create workspaces.

For GitHub, when creation is available:

1. Install the Hephaestus GitHub App on an organization.

Hephaestus creates the workspace from the installation.

For GitLab, when creation is available:

1. Link your account on the GitLab instance your deployment uses.
2. Enter an access token for that account.
3. Choose a group.
4. Complete the creation wizard.

The workspace belongs to that GitLab account.

1. If **Create workspace** is unavailable, ask an instance admin.

## Repositories

The connection determines repository access management.
For a **GitHub App** workspace, Hephaestus mirrors repositories granted to the app.
For a **token-managed** workspace, a workspace admin manages monitored repositories.

For a GitHub App workspace:

1. Change repository access in the app installation on GitHub.

For a token-managed workspace, as a workspace admin:

1. Open **Administration → Integrations → GitHub/GitLab → Manage repositories → Add a repository**.
2. Enter the full repository path.

**CAUTION:** Removal of a monitored repository permanently deletes its mirrored Hephaestus data.
To keep that data, do not remove the repository monitor.
The upstream repository does not change.

Initial sync time depends on the connected repositories' size and history.
Webhooks and scheduled reconciliation collect later changes.

## Members and teams

Members and teams belong to one workspace:

- GitHub App workspaces mirror organization members, teams, and repository access from GitHub.
- GitLab workspaces mirror the connected group and its projects.
- Workspace admins can review membership and role information under **Administration**.

If source-managed membership is incorrect:

1. Correct it in GitHub or GitLab.
2. Wait for the next sync.

## Practices and AI

Workspace admins choose:

- The active engineering practices.
- Each practice's feedback setting: **Off**, **Review before sending** (the default), or **Send automatically**.
- Whether practice reviews run automatically or permit manual requests.
- The connected AI model for practice reviews and Heph.
- The monthly AI spending cap.

**Review before sending** records observations but waits for workspace admin approval of feedback on the work.
Heph is available when the workspace has a model that meets your AI choice.
If you choose **No AI**, Heph does not answer.
These settings apply only to that workspace.
[Activity](./activity) is part of each workspace without its own setting.
That guide explains how to hide members or teams from workspace activity.

## Troubleshooting

For a missing workspace:

1. Confirm that your sign-in identity links to a workspace member.

For a missing repository:

1. Check the GitHub App installation or monitored repository list, as applicable to the connection.

For a repository or Slack channel sync error:

1. For a repository, open **Administration → Integrations → GitHub/GitLab → Manage repositories**.
2. For a Slack channel, open **Administration → Integrations → Slack**.
3. Check the affected resource's last error.
4. Check its access in the connected service.
5. Run a new sync.

Each error clears after its affected sync path succeeds.
A skipped pass keeps its error.

For a missing team:

1. Confirm that the team exists in the connected source platform.
2. Confirm that it has synced.

For a missing Practice profile:

1. Ask a workspace admin whether practice reviews are on in this workspace.

[Who can use Heph](./ai-mentor#who-can-use-heph) explains what to do if Heph does not answer.

## Your AI choice

Your choice applies across all your workspaces.

## GitLab token alerts

Hephaestus checks GitLab tokens daily and rotates them before expiry when GitLab permits it.
The connection page shows the expiry date or **no expiry**.

1. If rotation fails or GitLab refuses the token, replace it in workspace integration settings.

Your repositories and synced work stay.
Owners and administrators can enable **Workspace alerts** email in notification settings.
It reports tokens that need replacement and recovery after rotation or replacement.
Repeated checks of the same problem do not send duplicate alerts.
GitHub App tokens renew automatically.
Hephaestus does not track GitHub personal access token expiry.

## Unavailable repositories

For an unreadable monitored GitHub or GitLab repository, **Administration → Integrations** shows **Repository not found or not accessible**.
This does not prove deletion.
The name may have changed, or the connection may have lost access.
Hephaestus keeps the monitor and stored work.

After two consecutive unavailable responses, Hephaestus checks at most once each 24 hours.
Recent sync and backfill wait while the repository is unavailable.
A successful check clears the error and automatically resumes sync.
Connection authentication errors, rate limits, and network errors keep their normal retry behavior.

To recover:

1. Give the connection access to the repository again.
2. As a workspace admin, select **Sync now** on the connection to check immediately.

Otherwise, the check waits for its next daily run.

**CAUTION:** Removal of a monitor permanently deletes mirrored data, but not the upstream repository.
To keep mirrored data, do not remove the monitor.

If the repository is no longer wanted in the workspace:

1. For a GitHub App connection, change repository access in the installation.
2. For a token-managed connection, remove it from the monitored repositories.
